# REZICS 1.5.0

REZICS 1.5.0 makes Realm Rule authoring multilingual and non-destructive. Each
Rule in a replacement revision now carries a non-empty `localizations` array,
and the authoring read endpoint returns every stored localization. The web
editor keeps language-specific and shared drafts independently, persists them
in versioned browser storage, detects a newer server baseline, and supports
moving Rules up or down before publishing the next revision.

This is a breaking public API release. `PUT /api/v1/realms/{realmId}/rules`
removes the single Rule-level `language`, `title`, and `content` fields. It
requires `baseRevisionId` and accepts `localizations[]` for every Rule. The
matching public TypeScript client is `@rezics/api@1.9.0`.

No database migration is required: Rule content already uses the shared
`unit_localization` relation, whose `(unit_id, language)` identity supports the
new contract. Existing single-language Rule revisions remain valid and appear
as one-element localization arrays. Deploy the API, generated clients, and web
application together by following the coordinated cutover in
[Multilingual Realm Rule authoring](../architecture/realm-rule-localization-authoring.md#150-cutover).

# REZICS 1.3.0

REZICS 1.3.0 replaces the legacy recommendation projections with the sparse
`best` ranking contract and exposes readable source-Entity presentations on
accepted Unit external links.

## Breaking changes

- `POST /api/v1/feed/query` accepts only `best` and `new` for `sort`. The
  retired `hot`, `top`, and `rising` values are rejected.
- Accepted external links returned by Unit create, detail, update,
  variant-context, promotion, and localization operations now include the
  required `sourceEntity` presentation.
- The public TypeScript client for this contract is `@rezics/api@1.7.0`.

## Database cutover

This release performs an explicit maintenance cutover. The release controller
builds and imports every required image before it stops the recommendation
worker and API. A low-priority maintenance service returns HTTP 503 while the
database migration renames the sparse score projection, replaces the internal
Search candidate function, rebuilds the PGroonga index, and deletes the retired
`recommendation_unit_edge`, `recommendation_profile_interest`,
`recommendation_profile_signal_hourly`, and `recommendation_unit_stat` tables
in one database transaction. API and worker traffic resumes only from the 1.3.0
jobspecs after database and PGroonga index verification succeeds.

The deleted recommendation projections are derived data and are not rollback
artifacts. Before public traffic resumes, a failed cutover may restore the
pre-cutover database backup together with the 1.2.0 binaries. After traffic
resumes, repair forward instead of reversing the migration.

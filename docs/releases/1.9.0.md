# REZICS 1.9.0

REZICS 1.9.0 introduces the significant persisted and public contracts for
Zone composition, aggregate Block execution, semantic theming, and reviewed
custom Zone themes. The matching backend and web release is 1.9.0. The matching
breaking public TypeScript client release is `@rezics/api@1.11.0`.

This release supports v1.0.0-and-later data only and introduces no compatibility
alias for the superseded bare-Block-key execution routes or globally scoped
Block-key assumptions.

## Cutover order

1. Stop writes that create or replace Zone Pages, main Docks, Zone themes, and
   Book metadata. Keep ordinary reads available if the deployment platform can
   guarantee that old processes do not write the affected contracts.
2. Apply migration `20260826093708_zone_theme_review_pipeline.sql`. It adds the
   `zone_theme` Unit subtype and immutable revision/revision-asset tables, the
   review capabilities, the viewer custom-theme preference, the Book
   release-status access index, and bounded review-queue/revalidation indexes.
3. Deploy the 1.9.0 backend before the web client. The backend accepts and emits
   `BlockPath`, sibling-local Block keys, list presentation profiles, pinned
   sorts, derived sources, semantic style roles, extended theme tokens, and the
   custom-theme review API.
4. Regenerate and deploy the OpenAPI clients and then the 1.9.0 web application.
   The Zone Page performs one render projection read and one aggregate execution
   request; per-Block continuation remains available.
5. Install showcase packs whose `minRezicsVersion` is 1.9.0 only after the new
   backend is serving. Apply `hongloumeng`, `light-novel`, and the updated
   `vndb-v11` through the content-pack planner and verify the bundle checksum.
6. Resume writes after smoke checks confirm Page/Dock reads, Book status
   filtering, theme fallback, and the review queue. No dual-write period is
   required because all new document members are additive and old unsupported
   routes are not retained.

Before accepting submissions, provision separate reviewer and emergency-kill
roles and follow
[Zone theme review and incident response](../operations/zone-theme-review-and-response.md).
The backend database pool must contain at least three connections; aggregate
Zone execution admits at most `DATABASE_POOL_MAX - 2` concurrent Block jobs so
ordinary request traffic retains two connections.

## Persisted contract changes

- Block `_key` uniqueness is sibling-local. Query Blocks are addressed by a
  keyed structural `BlockPath` within the Page or Dock selected by the route;
  resource UUIDs are not copied into document JSON.
- Zone Page, Dock, and Wiki policies enforce their own depth, Block-count, and
  query-Block budgets. Page/Dock aggregate scheduling is a runtime cap and is
  never a cross-document write invariant.
- `book.release_status` becomes a typed Filter predicate supported by the
  `(release_status, id)` index.
- `zone_theme_revision` stores immutable source submissions, contract-scoped
  transformed CSS, static review evidence, render/AI evidence, and human/kill
  state. Contract-major revalidation runs exact source-version UUID keyset
  batches; failed static reviews fall back without corpus scans.

## Operational rollback

Application rollback before new writes may redeploy the previous processes and
leave the additive tables and columns present. After 1.9.0 documents, approved
theme revisions, or Book status filters have been written, roll forward instead:
the previous application does not understand their public contracts. Killing a
theme revision or disabling custom themes for a viewer is the supported
immediate presentation rollback and preserves token fallback.

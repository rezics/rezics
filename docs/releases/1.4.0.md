# REZICS 1.4.0

REZICS 1.4.0 replaces threshold-derived Unit reference states with factual
binary vote summaries. Alias and External Link resources no longer return
`accepted` or flat vote fields. They return `voteSummary`, support bounded
cursor pagination, and preserve withdrawn reference history. Unit Tag vote
mutations now return the same factual binary summary. The corresponding public
TypeScript client is `@rezics/api@1.8.0`.

This is a breaking API and persisted-contract release. Follow the coordinated
cutover in [Vote and reference governance](../architecture/vote-and-reference-governance.md#api-and-migration-cutover).

The database migration builds active-reference indexes concurrently, validates
binary aggregate parity, installs hard active/pinned limits, optimizes reference
aggregate updates, and removes withdrawn Aliases from search documents. Do not
run old and new API binaries against the migrated database at the same time.

A follow-up integrity migration closes six nullable `CHECK` paths, adds the
1,024-byte indexed fractional-position ceiling, repairs reference-limit locking
for direct `unit_id` moves, and leaves historical validation staged outside the
deployment transaction. See
[Data integrity and workload budgets](../architecture/data-integrity-and-workload-budgets.md).

The same unreleased 1.4.0 cutover also replaces content moderation reasons with
multi-rule content governance and multi-authority report referrals. Reports and
adverse decisions may cite multiple rules from the current Realm and the
official Rule Realm. Old moderation reports, cases, actions, notes, reasons,
notifications, and derived counters are intentionally discarded; there is no
data or API compatibility layer. Materialized Unit states and live account
enforcements remain authoritative. Deploy this change only as the coordinated
cutover documented in
[Content governance and reporting](../architecture/content-governance.md#140-cutover).

Notifications now expose typed, recipient-authorized destinations and every
notification row navigates to its corresponding feature or to a safe
recipient-only detail page. Clicking an unread row navigates immediately while
marking it read optimistically. Mark-all uses a per-recipient read-through
watermark instead of rewriting inbox history, and the Web badge no longer
renders estimation notation. This is a coordinated API, generated-client, Web,
and database cutover; follow
[Notification delivery and read state](../architecture/notification-delivery-and-read-state.md#140-api-and-migration-cutover).

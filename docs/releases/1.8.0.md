# REZICS 1.8.0

REZICS 1.8.0 replaces the previous split License paths with one registry,
one API field, and one independent grant ledger. Each License or rights statement may be
offered at the same time. `licenses` on write is the desired open offering set.
Public `licenses` are only open, recognized grants. Management reads must use
`licenseOfferings`, which includes invalidated open rows. The matching backend
and web release is 1.8.0; the matching breaking public TypeScript client
release is `@rezics/api@1.10.0`.

This is a coordinated breaking release of a persisted contract and the public
API. See [Unit license grants](../architecture/unit-license-grants.md).

## Cutover

- Stop application writes and apply the single atomic license migration. It
  asserts that the unused `unit_content_license` ledger is empty, reshapes it
  into `unit_license_grant`, imports the roughly 400,000 candidate Units,
  creates the required indexes, validates checks, and drops `unit.license`.
  A failed transaction leaves the old contract intact; no dual-read/write
  compatibility period is provided.
- Recognition is `recognized | invalidated`; offering end is a separate
  write-once pair of columns. Imported single-License declarations have a null
  grantor and use the cutover timestamp because the retired column retained no
  original actor or selection time.
- Governance action kinds `invalidate_content_license` and
  `restore_content_license` are renamed to `invalidate_license` and
  `restore_license`. `governance_decision.action` is an immutable text
  ledger: historical rows keep the old action strings.
- The platform capability `unit.content_license.manage` is renamed to
  `unit.license.manage`.
- Unit detail replaces `license` and `contentLicense` with public `licenses`
  and management `licenseOfferings`. Preference `defaultLicense` becomes
  `defaultLicenses`. Old clients must not treat the public array as the
  complete open set.
- `@rezics/license` exports the sole `LicenseIds`, `LicenseId`, and
  `LicenseRegistry` contract, including legal form, terms URL, SPDX identity,
  acknowledgement and ownership policy. Web code no longer constructs REZICS
  legal URLs or assembles separate License categories.
- License ID lists and License-specific policy are validated by the API. The
  database keeps only structural ledger constraints, so adding a registered
  License does not require scanning corpus-scale tables to replace enum-list
  checks.

## Legal copy

User Agreement §7.3 now describes independent prior authorizations, residual
rights for All rights reserved, and that ending an offering does not revoke
rights already obtained. That legal wording change is listed here for
maintainer confirmation before publication. The ledger does not infer the
legal time scope of a grant across later revisions or later contributions.

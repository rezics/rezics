# REZICS 1.7.0 governance Rule cutover

REZICS 1.7.0 replaces human governance reason enums with immutable Realm Rule
references and introduces an optional Zone-local Rule Realm. This is a breaking
database, API, generated-client, and Console release.

Every decision and its complete Rule basis are finalized atomically. The
database rejects unfinalized commits and any attempt to append, change, or
remove Rule references after finalization.

There is deliberately no enum-to-Rule mapping, compatibility alias, dual read,
or dual write. A legacy label such as `administrative` cannot prove which Rule
text and revision an operator applied. Migration
`20260811190001_governance_rule_decisions.sql` therefore refuses an in-place
upgrade when any Unit or user identity exists, and independently guards legacy
governance, account-state, merge, restriction, and audit rows.

## Cutover

1. Stop every pre-1.7 API, worker, and web process. Mixed versions are
   unsupported.
2. Take a restorable physical backup and verify it. This backup is for whole
   deployment rollback, not for importing reason codes.
3. Provision an empty replacement database, apply the complete migration
   directory, and install the 1.7 platform graph. The official Rule Realm is
   installed at revision 2 with the expanded governance rules.
4. If an environment must retain existing policy state, stop here. A maintainer
   must approve a separate, environment-specific re-attestation import whose
   operators select current Rule triplets. The release contains no automatic
   translation and must not fail open active restrictions.
5. Deploy the 1.7 API, generated clients, web application, and workers as one
   unit. Recreate any required governance state through the 1.7 APIs.
6. Run database replay/schema checks, bootstrap verification, seed checks, API
   contract tests, and representative indexed query plans before reopening
   traffic.

Rollback restores the backup and the complete 1.6 binary set. There is no
reverse data migration.

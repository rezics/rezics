# 通知、私信、反馈与运营后台

用户通过通知获知活动、经私信沟通、提交反馈/举报；运营团队在专用后台审核与处理。

## 场景 1：查看并管理通知列表

**入口/触发**：导航通知入口或 `/inbox/notification`。

**前置条件**：已登录。

**步骤**：
1. `/inbox/notification` → `NotificationPage` — `package/app/src/routes/_mainLayout/inbox/notification.tsx:1`–`10` → `package/app/src/inbox/pages/NotificationPage.tsx:13`–`70`。
2. `useNotifications(1,50)` — `NotificationPage.tsx:15` → `package/api/src/notification/notification.queries.ts:20`–`22` → `notificationApi.list()`（`GET /notification/list`，`package/api/src/notification/notification.api.ts:9`–`20`）。
3. 卡片列表按 latestAt 倒序 — `NotificationPage.tsx:53`–`67` → `package/app/src/inbox/components/NotificationCard.tsx:58`–`134`。
4. 点击卡片 `markAsRead` — `NotificationPage.tsx:59`–`62` → `package/api/src/notification/notification.mutations.ts`（`POST /notification/read`）。
5. 「全部已读」— `NotificationPage.tsx:26`–`34` → `notification.api.ts:36`–`40`（`POST /notification/read-all`）。
6. 跳来源内容 `resolveNotificationHref()` — `NotificationCard.tsx:72`（`package/app/src/inbox/models/notificationTarget`）。

**关键数据流**：`/inbox/notification` → `NotificationPage`/`NotificationCard` → list/markAsRead/markAllAsRead → `notify-boundary`（`package/server/src/notify-boundary/notify-boundary.client.ts`）→ 契约 `package/contract/src/notification/notify.ts`。

**边界/权限/异常**：所有登录用户可访问自己通知；空收件箱提示（`:47`–`50`）；失败提示（`:42`–`45`）；类型注册表 `package/contract/src/notification/kind-registry.ts`。

**入口/触发**：会话列表点击或 `/inbox/dm/$conversationId`。

## 场景 4：提交反馈/举报

**入口/触发**：反馈按钮或 `/feedback`。

**前置条件**：已登录。

**步骤**：
1. `/feedback` → `FeedbackPage` — `package/app/src/routes/_mainLayout/feedback/index.tsx:1`–`10` → `package/app/src/feedback/pages/FeedbackPage.tsx:16`–`80`。
2. 「提交反馈」打开抽屉 — `FeedbackPage.tsx:33`–`35` → `package/app/src/feedback/components/FeedbackDrawer`。

5. 后端 `POST /feedback` — `package/server/src/feedback/feedback.api.ts:40`–`56` → `feedbackService.create()`（`package/server/src/feedback/feedback.service.ts`）。

## 场景 11：拉黑/屏蔽用户

**入口/触发**：会话中「拉黑」或内容上下文菜单。

**前置条件**：已登录；会话已打开。

**步骤**：
1. 「拉黑」— `package/app/src/inbox/sections/ConversationThreadSection.tsx:140+`。
2. `useSetDmBlockMutation()` — `ConversationThreadSection.tsx:55` → `package/api/src/dm/dm.mutations.ts` → `POST /dm/blocks`（`package/api/src/dm/dm.api.ts:64`–`69`）。
3. 后端更新 UserBlock — `package/server/src/block/block.service.ts`。
4. 立即更新 `useDmBlockState(peerId)` — `ConversationThreadSection.tsx:54`。
5. 发送框禁用 — `:67`–`69`、`:150+`。
6. 被拉黑用户发送返回 403 — `package/server/src/notify-boundary/dm-boundary.api.ts:80`–`87`。

**关键数据流**：`ConversationThreadSection` → setBlock/getBlockState → `block.service.ts`（setBlock/isBlockedEitherWay）→ 契约 DmBlockState。

**边界/权限/异常**：禁止自我拉黑；重复拉黑幂等；拉黑后发送禁用且 403。

> 拉黑列表管理页：`package/app/src/routes/_mainLayout/user/me/setting/blocked.tsx`。

## 无权限时的拒绝流程

1. 前端 `useStaffConsoleAccess()` 检查 role 与 `hasGovernanceCapabilityHint()` — `package/app/src/staff/pages/shared.tsx:9`–`18`。
2. 失败渲染 `RouteDenied`（`package/app/src/core/routing/routeBoundaries.tsx:132`–`145`）或 `StaffForbiddenState`（`shared.tsx:75`–`90`）。
3. 后端 `governanceRoutePolicyService.decideForIdentity()`（`package/server/src/governance/governance.route.policy.service.ts`）。
4. 策略拒绝 403 → 前端捕获显示 `PolicyDenialNotice`。

# 帖子与讨论评论

帖子与评论是讨论的核心单元：根帖、续写接龙、嵌套回复、跨表面评论。帖子由统一的 Unit 模型承载，内容用 ContentDoc 存储；评论为带 depth 的树形结构；帖子可在全局或特定 realm 发布。

## 场景 1：新建一个根帖子

**入口/触发**：讨论/帖子页点击「发表观点」或创建表单。

**前置条件**：已登录；未被屏蔽/禁言。

**步骤**：
1. 点击回复框展开编辑器 — `package/app/src/comment/forms/ReplyComposer.tsx:89`–`92`。
2. 输入标题/正文/可选投票/语言 — `ReplyComposer.tsx:129`–`144`。
3. 「发表」触发 mutation — `ReplyComposer.tsx:169`–`186`（CreateRootPostInput）。
4. `POST /post`（normalizeCreatePostInput）— `package/api/src/post/post.api.ts:158`–`162`。
5. 后端 `assertPostCreatePolicy`（`package/server/src/post/post.api.ts:235`–`236`）+ `postService.create`（`:237`）。
6. 创建 Unit(POST)+Post+ContentTranslation — `package/server/src/post/post.service.ts`。
7. onSuccess 同步缓存 — `package/api/src/post/post.mutations.ts:120`–`150`。
8. 导航 `/post/$rootPostUnitId`。

**关键数据流**：`/post/$rootPostUnitId/` → `PostThreadPage` → `postQueries.detail()` → `POST /post` → `postService.create()` → Unit(POST)+Post+ContentTranslation → 契约 `PostResponse`。

**边界/权限/异常**：未登录拦截；被屏蔽 403（`post.api.ts:47`–`49`）；策略拒绝 403；标题/正文空禁用提交（`postEditorSurface.tsx:84`–`89`）。

## 场景 2：编辑帖子

**入口/触发**：详情页编辑按钮（作者/管理员）。

**前置条件**：作者或 admin；未锁定。

**步骤**：
1. 跳 `/post/$rootPostUnitId/edit` 或 `/realm/$realmId/post/$postUnitId/edit` — `package/app/src/post/pages/PostThreadPage.tsx:94`–`119`。
2. 编辑路由渲染 PostEditPage — `package/app/src/routes/_editor/post/$rootPostUnitId/edit.tsx:11`–`30`。
3. `postQueries.detail` + `unitQueries.languageContent` — `package/app/src/post/pages/PostEditPage.tsx:33`–`39`。
4. 修改标题/正文/语言 — `PostEditPage.tsx:40`–`52`。
5. 保存校验 — `PostEditPage.tsx:91`–`117`。
6. `PATCH /post/:unitId`（EditorialPatchSubmission）— `package/api/src/post/post.api.ts:203`–`211`。
7. `postService.update` 改 Unit/Post/ContentTranslation — `package/server/src/post/post.api.ts:344+`。
8. onSuccess 刷新 — `package/api/src/post/post.mutations.ts:187`–`202`。

**关键数据流**：`/post/$rootPostUnitId/edit` → `PostEditPage` → detail+languageContent → `PATCH /post/:unitId` → `postService.update()` → 缓存。

**边界/权限/异常**：非作者/管理员隐藏按钮；锁定 403；冲突 `getLockedFieldError`（`PostEditPage.tsx:60`–`68`）；语言回退 locale。

## 场景 3：对帖子续写（长帖接龙）

**入口/触发**：详情页「继续讨论/添加节点」。

**前置条件**：有权限；续写是评论的特殊型。

**步骤**：
1. ReplyComposer parentCommentId 模式 — `package/app/src/comment/forms/ReplyComposer.tsx:149`–`166`。
2. 「发表」触发 commentMutation — `ReplyComposer.tsx:151`–`165`。
3. `POST /comment/`（CreateCommentInput）— `package/api/src/comment/comment.api.ts:30`–`35`。
4. `commentService.create` 计算 depth=parentDepth+1 — `package/server/src/comment/comment.service.ts:64`–`72`。
5. 映射 DTO — `package/server/src/comment/comment.mapper.ts:5`–`53`。
6. onSuccess 追加 — `package/api/src/comment/comment.mutations.ts:39`–`54`。
7. `/post/$rootPostUnitId/continue/$unitId`（unitId=CommentID）— `package/app/src/routes/_mainLayout/post/$rootPostUnitId/continue.$unitId.tsx:8`–`12`。
8. `ContinueThreadPage` 以该评论为锚点显示回复树 — `package/app/src/comment/pages/ContinueThreadPage.tsx:20`–`123`。

**关键数据流**：`PostThreadPage` → ReplyComposer(parentCommentId) → `POST /comment/` → `commentService.create()` → Comment(depth≥2) → `/continue/$unitId` → `ContinueThreadPage`。

**边界/权限/异常**：parentCommentId 与 rootUnitId 不匹配 400；depth 无明确上限；删除/移除评论 isRedacted=true。

## 场景 4：在 Realm 内编辑帖子

**入口/触发**：realm 帖子详情（`/realm/$realmId/post/$postUnitId`）编辑。

**前置条件**：作者或 realm 管理员；帖子已关联该 realm。

**步骤**：
1. `PostThreadPage` context.kind="realm" 跳编辑 — `package/app/src/post/pages/PostThreadPage.tsx:102`–`113`。
2. 编辑路由 returnTo 指向 realm — `package/app/src/routes/_editor/realm/$realmId/post/$postUnitId/edit.tsx:15`–`34`。
3. 同场景 2 流程。

**关键数据流**：realm 帖子 → 编辑 → `PostEditPage` → `PATCH /post/:unitId` → 返回 realm 详情。

**边界/权限/异常**：帖子未在 realm（UnitRealm 不存在）context 不可用；参数不匹配应重定向；realm 本地 moderationStatus=REMOVED 软删除。

## 场景 5：查看帖子详情与续写链

**入口/触发**：点击帖子卡片或搜索结果。

**前置条件**：PUBLISHED（或作者/管理员见 DRAFT）。

**步骤**：
1. `/post/$rootPostUnitId` — `package/app/src/routes/_mainLayout/post/$rootPostUnitId/index.tsx:13`–`28`。
2. `postQueries.detail(rootPostUnitId)` — `package/app/src/post/pages/PostThreadPage.tsx:47`–`53`。
3. PostResponse 含 title/content(ContentDoc)/author/replyCount/lastReplyAt — `package/contract/src/post/post.ts:148`–`220`。
4. `PostDetail` 渲染 — `package/app/src/post/components/detail/PostDetail.tsx`。
5. `CommentThreadSection` 加载根评论树 — `package/app/src/comment/sections/CommentThreadSection.tsx`（commentDiscoveryInfiniteQuery）。

7. `ContinueThreadPage` 锚点 + 后代树 — `:80`–`103`。

**关键数据流**：`/post/$rootPostUnitId` → `PostThreadPage` → `postQueries.detail()` → `GET /post/:unitId` → `postService.getByUnitId()` → `mapPostToDTO()` → CommentThreadSection（commentDiscoveryInfiniteQuery）。

**边界/权限/异常**：删除 isTombstone 占位；DRAFT 未登录不可见；移除 isRedacted；`?focusPostUnitId=` 高亮（`PostThreadPage.tsx:68`–`69`）。

## 场景 6：在帖子或作品上发表评论

**入口/触发**：帖子/作品讨论区点击「添加评论」。

**前置条件**：已登录；未屏蔽；targetUnitId 有效。

**步骤**：
1. ReplyComposer 回复模式 targetUnitId 指向作品 — `package/app/src/comment/forms/ReplyComposer.tsx:50`–`58`。
2. 输入正文 → 提交 — `ReplyComposer.tsx:147`–`203`。
3. 无 parentCommentId 时作为根级评论发 `POST /post/`（kind=POST）— `ReplyComposer.tsx:169`–`186`。
4. 或有 parentCommentId 发 `POST /comment/` — `ReplyComposer.tsx:151`–`165`。
5. 后端创建 Post 或 Comment（PUBLISHED）— `package/server/src/post/post.api.ts:232`–`252` 或 `package/server/src/comment/comment.api.ts:106`–`121`。
6. onSuccess 刷新 — `package/api/src/comment/comment.mutations.ts:39`–`54` 或 `package/api/src/post/post.mutations.ts:120`–`150`。

**关键数据流**：详情页 → ReplyComposer(targetUnitId) → `POST /post/` 或 `POST /comment/` → create() → DTO → 缓存刷新。

**边界/权限/异常**：锁定 403；策略限流；空内容禁用；targetUnitId 无效抛错。

## 场景 7：回复评论（嵌套/楼层）

**入口/触发**：某条评论下「回复」。

**前置条件**：已登录；父评论存在未删除；rootUnitId/realmUnitId 匹配。

**步骤**：
1. `CommentReply` 显示「回复」— `package/app/src/comment/components/item/CommentReply.tsx`。
2. 展开内联 ReplyComposer(parentCommentId) — `package/app/src/comment/sections/CommentTreeNode.tsx`。
3. parentCommentId 模式 — `package/app/src/comment/forms/ReplyComposer.tsx:116`。
4. 提交 — `ReplyComposer.tsx:149`–`165`。
5. `POST /comment/` — `package/api/src/comment/comment.api.ts:30`–`35`。
6. `commentService.create` 取父并计算 depth — `package/server/src/comment/comment.service.ts:63`–`72`。
7. 创建 Comment（parentCommentId/depth/isLocked 继承/replyCount=0）。
8. 父 replyCount/lastReplyAt 更新。

**关键数据流**：CommentReply → ReplyComposer(parentCommentId) → `POST /comment/` → `commentService.create()` → Comment 行 → 树刷新。

**边界/权限/异常**：父无效/删除 400；depth 无上限但 UI 可能限渲染深度；父锁定拒绝 403；rootUnitId 不匹配 400。

## 场景 8：编辑或删除自己的评论

**入口/触发**：自己的评论上「编辑/删除」。

**前置条件**：作者；未删除/移除。

**步骤**：
1. 编辑入口 — `package/app/src/comment/components/item/CommentReply.tsx`。
2. `PATCH /comment/:id`（UpdateCommentInput）— `package/api/src/comment/comment.api.ts:37`–`45`。
3. `commentService.update` 校验作者 — `package/server/src/comment/comment.service.ts`；改 content/updatedAt — `package/server/src/comment/comment.api.ts:122`–`141`。
4. 删除 `DELETE /comment/:id` — `package/api/src/comment/comment.api.ts:57`–`61`。

**边界/权限/异常**：非作者 403；删除幂等；移除后作者仍可改但显示已移除。

## 场景 10：评论触发通知（dispatch）

**入口/触发**：提交评论/帖子后生成通知。

**前置条件**：创建成功；目标用户满足通知条件。

**步骤**：
1. create 完成写库 — `package/server/src/comment/comment.service.ts:64`–`72`、`package/server/src/post/post.service.ts`。
2. 可能触发 dispatch — `package/server/src/dispatch/dispatch.service.ts`。
3. **注**：当前 dispatch.service 主要做元数据同步（翻译/credit/书游媒信息），评论/帖子推送通知由其他机制（webhooks/job queue）实现，代码中未见明确推送实现。

**关键数据流**：create → service → DTO →（潜在）dispatch → 通知队列。

**边界/权限/异常**：作者自通知应过滤（未明确）；禁用通知/屏蔽抑制；@提及解析未见实现；批量创建可能通知风暴。

## 场景 11：帖子与评论的 Unit 统一模型

- **帖子**：每个 Post 对应一个 Unit(type=POST)，unitId 相同 — `package/server/src/db/schema/post.ts:28`–`78`、`package/server/src/db/schema/unit.ts:90`–`250`；DTO 合并 — `package/contract/src/post/post.ts:148`–`220`。
- **评论**：Comment **无对应 Unit 行**，独立存在 — `package/server/src/db/schema/comment.ts:29`–`109`；DTO 中 id=unitId（向后兼容）— `package/server/src/comment/comment.mapper.ts:5`–`53`。
- **ContentDoc**：Post 与 Comment 的 content 都遵循 ContentDoc — `package/contract/src/content/doc-v1.ts:52`–`71`（main=markdown，可含 poll/unit-ref 块，`:28`–`50`）。
- **生命周期 state**：Post 由 `extra.stateSchemaTag` 指向的 schema 管控（`package/contract/src/post/post.ts:129`–`138`、`package/contract/src/post/state-schema.ts`）。

| 属性 | Post（Unit+Post） | Comment（独立行） |
|------|------------------|------------------|
| 身份 | Unit.id=Post.unitId | Comment.id（UUID7，无 Unit） |
| 根讨论 | 自身 | Comment.rootUnitId → Unit(POST) |
| 作者 | Unit.userId=Post.authorUserId | Comment.authorUserId |
| 内容 | ContentTranslation(多语言) | Comment.content(单一 JSON) |
| 嵌套 | 顶层 | Comment.depth |
| 软删除 | Unit.status=DELETED | Comment.deletedAt |
| 审核 | governance 表 | Comment.moderationStatus |

## 综合生命周期

发起根帖（`POST /post`）→ 评论（`POST /comment`，depth=1）→ 续写（`POST /comment` w/ parentCommentId，depth≥2）→ 编辑（`PATCH`）→ 删除（`DELETE`/软删）→ 排序分页（`GET /comment/list`）→ 提交 realm（`POST /post/:id/submit-to-realm` 创建 UnitRealm）→ 通知（dispatch，可选）→ 采纳答案（`POST /post/accepted-answers` 创建 CommentPromotion）。

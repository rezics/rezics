# 认证、账户操作、个人主页与设置

本簇涵盖 Rezics 中用户身份认证、账户管理、个人档案展示和系统设置等核心场景：登录/注册、邮箱验证、补全注册、密码重置、个人主页浏览与编辑、关注、账户安全、主题/语言切换、会话初始化等。

## 场景 1：注册新账号

**入口/触发**：未登录用户点击注册链接或登录页的「创建账号」按钮。

**前置条件**：未登录状态。

**步骤**：
1. 用户导航至 `/register` — `package/app/src/routes/_mainLayout/register.tsx:8` 定义路由。
2. 页面加载 `RegisterPage` — `package/app/src/user/pages/RegisterPage.tsx:40`，用户输入邮箱、密码、确认密码。
3. 点击「注册」触发 `register()` handler — `package/app/src/user/models/handler.ts:20`，执行客户端校验与服务通信。
4. Handler 调用 `authApi.signUp()` — `package/app/src/user/pages/RegisterPage.tsx:79` → `package/api/src/auth/auth.api.ts:97`，发送 `POST /auth/sign-up/email`。
5. 后端处理注册并返回响应。
6. 前端调用 `hydrateAuthSessionState()` — `package/app/src/user/models/handler.ts:30` 刷新会话状态。
7. 成功后重定向至 `/complete-registration` — `package/app/src/user/pages/RegisterPage.tsx:92`。

**关键数据流**：`register.tsx:8` → `RegisterPage.tsx:40` → `handler.ts:20` → `authApi.signUp() auth.api.ts:97` → 后端 auth-boundary/认证服务 → `hydrateAuthSessionState()`。

**边界/权限/异常**：邮箱格式与密码复杂度校验；确认密码不一致报错；邮箱已存在时后端返回错误并提示；成功后须进入补全流程。

## 场景 2：邮箱验证与 OTP 确认

**入口/触发**：注册成功后自动进入 `/complete-registration`，或用户按需验证邮箱。

**前置条件**：已注册，处于未验证/补全阶段。

**步骤**：
1. 进入 `CompleteRegistrationPage` — `package/app/src/routes/_mainLayout/complete-registration.tsx:8`，由 `registration.stage === 'verify-email'` 触发。
2. 显示 `EmailVerificationStep` — `package/app/src/user/pages/CompleteRegistrationPage.tsx:313`。
3. Turnstile 人机校验 — `package/app/src/user/pages/CompleteRegistrationPage.tsx:447`。
4. 点击「发送验证码」→ `authApi.sendVerificationOTP()` — `CompleteRegistrationPage.tsx:385` → `package/api/src/auth/auth.api.ts:162`，`POST /auth/email-otp/send-verification-otp`。
5. 后端发送 OTP，前端开始 60s 冷却 — `CompleteRegistrationPage.tsx:392`（冷却时限存 localStorage）。
6. 在 `OtpInput` 输入 6 位验证码 — `CompleteRegistrationPage.tsx:505`。
7. 点击「验证」→ `authApi.verifyEmailOTP()` — `CompleteRegistrationPage.tsx:411` → `auth.api.ts:174`，`POST /auth/email-otp/verify-email`。
8. 成功后 `handleEmailComplete()` — `CompleteRegistrationPage.tsx:567` → `authApi.materializeAccount()` — `CompleteRegistrationPage.tsx:572` → `auth.api.ts:311`，`POST /auth/account/materialize` 创建主 Rezics 用户。

**关键数据流**：`complete-registration.tsx:8` → EmailVerificationStep → `sendVerificationOTP` → email-otp service → `verifyEmailOTP` → `materializeAccount` → `hydrateAuthSessionState()`。

**边界/权限/异常**：Turnstile 加载失败提示；OTP 过期/无效报错；冷却期内按钮禁用；邮箱已验证则跳过。

## 场景 3：补全注册信息（账户设置）

**入口/触发**：邮箱验证完成后自动进入，或返回 `/complete-registration` 继续设置。

**前置条件**：邮箱已验证，`registration.stage === 'setup-account'`。

**步骤**：
1. 显示 `IdentityStep` — `package/app/src/user/pages/CompleteRegistrationPage.tsx:141`。
2. 填写显示名、slug、语言偏好 — `CompleteRegistrationPage.tsx:246`–`300`。
3. slug 变化时自动检查可用性 — `CompleteRegistrationPage.tsx:192` → `authQueries.slugAvailability(slug)`（`package/api/src/auth/auth.queries.ts`）。
4. 提交 → `authApi.setupProfile()` — `CompleteRegistrationPage.tsx:214` → `package/api/src/auth/auth.api.ts:320`，`POST /auth/account/profile-setup`。
5. 后端创建/激活档案。
6. `handleAccountSetupComplete()` — `CompleteRegistrationPage.tsx:562` 刷新会话并重定向首页 — `CompleteRegistrationPage.tsx:564`。

**关键数据流**：IdentityStep → slugAvailability → `setupProfile()` → profile-setup service → `hydrateAuthSessionState()` → 重定向。

**边界/权限/异常**：slug <6 字符或被占用报错；语言列表来自 `LANGUAGES`（`CompleteRegistrationPage.tsx:56`）；超时可 `authApi.renewProfileSetupToken()`（`auth.api.ts:329`）。

## 场景 4：登录

**入口/触发**：访问受保护页面或主动点击登录。

**前置条件**：未登录。

**步骤**：
1. 导航至 `/login` — `package/app/src/routes/_mainLayout/login.tsx:8`。
2. 加载 `LoginPage` — `package/app/src/user/pages/LoginPage.tsx:40`，输入邮箱密码。

4. 调用 `authApi.signIn()` — `package/api/src/auth/auth.api.ts:90`，`POST /auth/sign-in/email`。
5. 后端验证凭证返回认证会话。

**边界/权限/异常**：空字段校验；认证失败报错；多次失败可能触发限流；未完成注册者重定向 `/complete-registration`。

## 场景 5：登出

**入口/触发**：菜单或设置页点击登出。

**前置条件**：已登录。

**步骤**：
1. 触发 `logout()` — `package/app/src/user/models/handler.ts:38`。
2. `authApi.signOut()` — `package/api/src/auth/auth.api.ts:111`，`POST /auth/sign-out`。
3. 后端清除认证会话。
4. `clearAuthSessionState()` — `handler.ts:40` 清空状态存储。
5. 重置 `useAuthSessionStore`/`useUserProfileStore` — `handler.ts:41`–`42`。
6. 清除相关 React Query 缓存 — `handler.ts:43`–`44`。
7. 页面刷新 — `handler.ts:47`（可用 `disableReload` 关闭，用于补全注册流程）。

**关键数据流**：`logout()` → `signOut()` → 会话清除 → `clearAuthSessionState()` → 清缓存 → 刷新。

**边界/权限/异常**：网络错误时仍清空本地状态；`disableReload=true` 支持不刷新登出。

## 场景 6：忘记/重置密码

**入口/触发**：登录页点击「忘记密码」或邮件中的重置链接。

**边界/权限/异常**：token 无效/过期显示错误并可重新申请（`ResetPasswordPage.tsx:47`–`49`）；为安全起见邮箱不存在可能返回泛化消息。

**关键数据流**：受保护路由 → 会话检查 → `RouteUnauthenticated` → `/login` → 恢复目标。

**边界/权限/异常**：未完成注册的已认证用户重定向 `/complete-registration`；权限不足显示 `RouteDenied`。

## 补充：认证边界与状态模型

- 认证边界：`/auth/*` 由 `auth-boundary`（`package/server/src/auth-boundary/`）作为独立认证服务（`package/auth`）与主应用的网关；session token 与 profile-setup token 分阶段使用，JWT + Cookie 管理会话。
- 状态：`useAuthSessionStore`（认证状态/注册阶段/权限）、`useUserProfileStore`（当前档案）；`hydrateAuthSessionState()` 在启动与登录/登出后同步。
- 权限：`routeBoundaries()` 在路由级统一处理（未认证→`RouteUnauthenticated`、无权限→`RouteDenied`、加载→`RouteLoading`、错误→`RouteError`）。

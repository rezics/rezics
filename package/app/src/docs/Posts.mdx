# Posts & threading

Posts power both flat preview streams and the deep threaded discussions on the
post detail surface. The split between preview and thread components is
intentional:

- **`StreamPostCard`** — flat single-post preview surface owned by the stream
  feature.
- **`CommentReply`** — tree node with collapse/expand + threading rail + reply
  composer slot. 6 props.

Thread layout tests belong on CommentReply because it renders the threading rail
and collapse toggle that stream previews do not have. See
[`Foundation/Patterns`](?path=/docs/foundation-patterns--docs).

## Composition parts

The thread is composed from small parts that compose freely:

- [`StreamPostCard`](?path=/docs/app-stream-stream-cards--docs)
- [`PostAuthorHeader — Default / Compact`](?path=/story/domain-post-postauthorheader--default)
- [`PostBodyMarkdown — Default / LongContent / Empty`](?path=/story/domain-post-postbodymarkdown--default)
- [`CollapseToggle — Default / Compact`](?path=/story/domain-post-collapsetoggle--default)

## Tree section

`CommentThreadSection` orchestrates the whole tree from a `rootPostUnitId`. The
data-shape stories cover the four interesting axes:

- [`CommentThreadSection — Default / Empty / Flat / Threaded3Deep / Threaded10Deep`](?path=/story/app-comment-commentthreadsection--default)
- [`ReplyComposer — Default / Compact / Empty / HappyPath`](?path=/story/app-comment-replycomposer--default)

# Elevation

**Default policy is flat.** Surfaces separate via whitespace, tonal fills, or
explicit card surface choices. Shadows are reserved for the modal tier, true
float-above-canvas surfaces, and shadcn `<Card surface="elevated">` media
cards. Elevated Card hover lift is enabled only by `interactive`. Source:
`package/ui/src/config/tokens/elevation.ts`.

`Card surface="elevated"` exposes `elevation={1..10}` for card-specific
calibration. The scale still resolves through the Card API; consumers should not
hand-roll shadow utilities on card instances.

This keeps the parchment-archive feel — the page is calm, layers are quiet, and elevation is something you only feel when it really means *I am temporarily on top*.

## When to use what

| Tier | Token | Use |
| --- | --- | --- |
| flat (default) | none | Sections, table rows, `Card surface="plain"`, `Card surface="contained"` |
| 1 | `--shadow-1` | `Card surface="elevated"` media-rich recommendation/article cards; sticky bars |
| 2 | `--shadow-2` | Elevated interactive card hover, dropdowns, popovers, floating action menus |
| 3 | `--shadow-3` | Exceptional floating surfaces |
| modal | `--shadow-modal` | Modals, dialogs, full overlays |

Dark mode shadows scale up opacity (×5) so they stay perceptible against deeper canvas tones.

## Usage

```tsx
// MUI sx — radius via theme.shape, color/shadow via CSS vars
<Box sx={{
  borderRadius: 1.5,                                 // theme.shape.borderRadius * 1.5
  background: "var(--colors-surface-elevated)",
  boxShadow: "var(--shadow-modal)",
}}>

// UnoCSS — utilities resolve through theme
<div className="rounded-lg bg-surface-elevated shadow-modal">
```

Don't hand-roll `shadow-md` to "make a card stand out." Use shadcn `<Card surface="elevated">` when the item is media-rich and should read like a recommendation/article card; otherwise use `surface="plain"` or `surface="contained"`.

## Reference

# Spacing

UnoCSS classes (`p-N`, `gap-N`, `mt-N`, …) follow Tailwind v4's single-`--spacing` model: every step is `N × 4px`. So `p-8 = 32px`, `gap-3 = 12px`.

Source of truth: `package/ui/src/config/tokens/spacing.ts` (docs reference).

Any integer N produces `N × 4px` — these are just the rhythm steps the design system actually uses. Avoid arbitrary in-between values like `p-7` (28px) — if a step feels off, the surrounding rhythm is the problem, not the scale.

## Common patterns

| Use | UnoCSS | Pixels |
| --- | --- | --- |
| Inline icon-to-label gap | `gap-2` | 8px |
| Form field row gap | `gap-3` | 12px |
| Card padding | `p-4` | 16px |
| Section internal padding | `p-6` | 24px |
| Section divider rhythm | `p-8` | 32px |
| Between sections (app default) | `p-12` | 48px |
| Page-level vertical rhythm | `p-16` | 64px |
| Hero / chapter-level breathing | `p-24` | 96px |

## Usage

```tsx
// UnoCSS — N × 4px
<div className="p-4 gap-2">            // padding: 16px, gap: 8px
<section className="py-12 gap-8">      // py: 48px, gap: 32px

// TS source (rare — only for generating CSS outside UnoCSS)
import { spacing } from "@rezics/ui/config/tokens/spacing";
```

Don't introduce off-grid values. If 12px feels right but the next step (24px) feels too big, the spacing rhythm of the surrounding section is probably wrong, not the scale.

# Layout & Breakpoints

rezics ships **seven** breakpoints. Five are the modern Tailwind set; the two rezics-specific additions — `xsm` and `8xl` — anchor the small-end and large-end edges that the Tailwind defaults miss for our content shape.

| Token | Value | Anchored to | Notes |
| --- | --- | --- | --- |
| `xs` | `0px` | small phones | base, no media query needed |
| `xsm` | `450px` | tall phones | rezics-specific |
| `sm` | `640px` | landscape phones / small tablets | Tailwind default |
| `md` | `768px` | tablets | Tailwind default |
| `lg` | `1024px` | small laptops | Tailwind default |
| `xl` | `1280px` | desktops | Tailwind default |
| `2xl` | `1536px` | large desktops | Tailwind default |
| `8xl` | `1440px` (container only) | reading containers | rezics-specific |

## Container widths

Containers cap content width at the breakpoint they match:

```tsx
<div className="container mx-auto">…</div>
```

The `8xl` container is rezics-specific: a `1440px` content cap intended for ultra-wide reading layouts (long-form chapters with side annotation rails on a 27-inch display). It is **not** present as a media-query breakpoint — only as a container size — because we don't want layout reflows triggered at that width, only a content-width clamp.

## Why `xsm`

The Tailwind default jumps from `0` (xs) to `640` (sm). rezics sees actual phone widths cluster around 360–430px (modern iPhones / Pixels) where the page can comfortably afford a two-column meta + body layout that doesn't fit at 360px. `xsm: 450px` is the anchor that lets us shift from a single-column phone layout into a slightly denser one before the tablet break at `md: 768px`. The split is grounded in our analytics, not in a generic device list.

## Why `8xl` (container only)

A `2xl: 1536px` page on a 27-inch / 32-inch monitor exceeds comfortable reading-line lengths. Reading view caps at `8xl: 1440px` to keep prose lines at ~75 characters without forcing the entire app down to that size. The rest of the layout (sidebar, navigation chrome) gets the `2xl` breakpoint; only reading-content containers reach for `8xl`.

## Reference

> **Tailwind breakpoints**: tailwindcss.com/docs/responsive-design — `sm`/`md`/`lg`/`xl`/`2xl` are adopted as-is. **Apple HIG layout**: developer.apple.com/design/human-interface-guidelines/layout — the "different content at different sizes" sensibility is what motivates the `8xl`-as-container-only split. rezics adds `xsm` (small-screen anchor) and `8xl` (large-screen reading cap) to the Tailwind default set.

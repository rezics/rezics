# Density

rezics treats density as an **intrinsic property of each component type**. A table row is naturally dense, a list item is more relaxed, and a breadcrumb item is tight because it lives beside text. Density is encoded in component vocabulary, not in a user-facing mode switch.

## What density changes

Density emits nine fixed-value component-tier padding tokens:

| Token | Value | Intent |
| --- | --- | --- |
| `--padding-breadcrumb-y` | `4px` | Sibling-of-text affordance. |
| `--padding-menu-item-y` | `8px` | Dropdown and context-menu rows. |
| `--padding-table-row-y` | `12px` | Scannable data rows. |
| `--padding-toolbar-y` | `8px` | Repeating chrome rows. |
| `--padding-formfield-y` | `4px` | Form controls. |
| `--padding-sidebar-item-y` | `8px` | Navigation rows. |
| `--padding-tab-item-y` | `4px` | Tabs list items. |
| `--padding-command-item-y` | `8px` | Command-palette rows. |
| `--padding-list-item-y` | `12px` | Primary touch-affinity rows. |

A density-aware rezics-authored composite consumes one of these tokens. Everything else stays on fixed spacing utilities.

## What density never changes

Density affects **only** padding, gap, min-height, and similar spacing dimensions. It SHALL NOT touch:

- `font-size`
- `line-height`
- `letter-spacing`
- `font-weight`

Both Apple HIG and MD3 forbid this for legibility. Type carries information; reflowing it across density modes breaks reading habits. rezics adopts the same constraint.

## Opt-in / opt-out

| Opt in (density-aware) | Opt out (density-fixed) |
| --- | --- |
| Table row | Hero sections |
| List item | Reading view |
| Toolbar | Book covers |
| FormField (TextField, Select, Combobox) | Dialog **content** surfaces |
| Sidebar item | Onboarding screens |
| MenuItem (dropdown / context) | Marketing surfaces |
| TabsList item | |
| Breadcrumb item | |
| CommandPalette item | |

The dialog **frame** may opt in when it owns chrome rows; dialog content does not. Reading and form layouts inside should keep their own local rhythm.

Adding a new density-aware component requires an OpenSpec change that adds a fixed `--padding-*` token in `uno-config.ts` and wires a rezics-authored consumer to that token.

## Reference

> **MD3 density**: m3.material.io/foundations/layout/applying-layout/window-size-classes — the 4-step density model is the engineering reference, but rezics adopts only the idea that repeating surfaces need explicit spacing vocabulary. Apple HIG offers no token vocabulary for density; we use HIG's "type carries information" sensibility to forbid type changes across tiers. Spec: `openspec/specs/design-system-density/spec.md`.

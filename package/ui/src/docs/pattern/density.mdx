# Density

rezics ships density as a **three-mode user-facing system**: `compact`, `comfortable`, `spacious`. The default is comfortable. Density propagates as a class on `<html>` (no class = comfortable, `density-compact`, `density-spacious`) and coexists with the `.dark` theme switch on the same root.

The Density toolbar at the top right of every Storybook page flips the global mode in real time. The same surface a contributor sees is the same surface in production — there is no separate "demo mode."

## What density changes

Density adjusts a single system-tier knob, `--density-step`:

| Mode | `--density-step` | Intent |
| --- | --- | --- |
| Compact | `-2px` | Admin tables, editor toolbars, dense data lists, debug overlays. |
| Comfortable | `0px` | Default consumer-facing app. Cards, navigation, forms, dialogs. |
| Spacious | `+2px` | Hero sections, reading view, onboarding flows, marketing. |

Component-tier `--padding-*` tokens (`--padding-table-row-y`, `--padding-list-item-y`, `--padding-formfield-y`, …) resolve to `calc(<base> + var(--density-step))`. A density-aware composite consumes those tokens; everything else stays on fixed spacing utilities.

## What density never changes

Density affects **only** padding, gap, min-height, and similar spacing dimensions. It SHALL NOT touch:

- `font-size`
- `line-height`
- `letter-spacing`
- `font-weight`

Both Apple HIG and MD3 forbid this for legibility. Type carries information; reflowing it across density modes breaks reading habits. rezics adopts the same constraint.

## Opt-in / opt-out

| Opt in (density-aware) | Opt out (density-fixed) |
| --- | --- |
| Table row | Hero sections |
| List item | Reading view |
| Toolbar | Book covers |
| FormField (TextField, Select, Combobox) | Dialog **content** surfaces |
| Sidebar item | Onboarding screens |
| MenuItem (dropdown / context) | Marketing surfaces |
| TabsList item | |
| Breadcrumb item | |
| CommandPalette item | |

The dialog **frame** opts in (small breathing-room differences read at the chrome level); the dialog content does not (reading and form layouts inside should not move when density flips).

Adding a new density-aware component requires: (1) a component-tier `--padding-*` token in `uno-config.ts`, (2) a consumer wiring the component to that token, (3) a `WithDensity` story added to the component's story file.

## Per-app default

| App | `<html>` class on mount |
| --- | --- |
| `@rezics/admin` | `density-compact` |
| `@rezics/app` | (none — comfortable) |
| `@rezics/folio`, `@rezics/editor` | (none — comfortable) |

The user MAY override via a preference setting; the override adds or removes the corresponding class on `<html>`.

## Why three, not four

<Compare>
  <Do caption="Three labeled modes — clear intent">
    Compact / Comfortable / Spacious — each label maps to a use case (dense data, default app, leisurely reading). Reviewers can read a screenshot and know the density at a glance.
  </Do>
  <Dont caption="MD3's four numeric steps">
    `default / -1 / -2 / -3` is engineered for pointer-driven dense pro tools. rezics is reading-and-browsing software with admin areas; the asymmetric "1 dense, 1 default, 1 leisurely" matches the actual use cases. Numeric labels also push the cognitive load of picking a mode onto every consumer.
  </Dont>
</Compare>

## Reference

> **MD3 density**: m3.material.io/foundations/layout/applying-layout/window-size-classes — the 4-step density model is the engineering reference. rezics maps it to three labeled modes (`compact` / `comfortable` / `spacious`) for clarity. Apple HIG offers no token vocabulary for density; we use HIG's "type carries information" sensibility to forbid type changes across modes. Spec: `openspec/specs/design-system-density/spec.md`.

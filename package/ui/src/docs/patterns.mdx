# Patterns — Do / Don't

Code-level patterns. The "why" lives in [Voice](?path=/docs/foundation-voice--docs); the "what" lives in [Tokens](?path=/docs/foundation-tokens-colors--docs). This is the "how it should look in JSX/CSS".

This page is the human-readable counterpart to `.claude/skills/rezics-design/patterns.md`.

---

## 1. Section / page layout

Sections separate via `space-8` (48px) vertical padding. No card wrap, no border, no shadow.

```tsx

  <Typography variant="h2">Recent Books</Typography>

```

Bordered/shadowed section cards are the SaaS-dashboard look. Rezics is a library — sections breathe through whitespace.

## 2. Cards (book / item / post)

Image, title, author — that's the card. The cover art carries the visual weight. Whisper border for table-row separation is fine; it's containment, not chrome.

## 5. Links

`<SafeLink>` classifies external URLs and routes them through a confirmation modal. Enforced by R5 in `bun run check:convention`.

```tsx
// Do
import { SafeLink } from '@rezics/ui';
<SafeLink href={url}>Read on Goodreads</SafeLink>

// Don't — raw <a> fails check:convention
<a href={url}>Read on Goodreads</a>

// Don't — MUI Link bypasses safety for external URLs
<Link href={externalUrl}>Read on Goodreads</Link>
```

MUI `<Link>` is fine for in-app navigation (TanStack Router, internal anchors). For anything that leaves rezics, `<SafeLink>` only.

## 6. Icons

`@mui/icons-material` is the default. `lucide-react` for icons MUI lacks. Emoji are content — what users post — not UI vocabulary.

```tsx
// Do
import BookmarkIcon from '@mui/icons-material/BookmarkBorder';
import { Heart } from 'lucide-react';
<IconButton><BookmarkIcon /></IconButton>
<Heart size={16} />

// Don't
<button>📚 My Library</button>
<span>❤️ Like</span>
<svg viewBox="0 0 24 24"><path d="..." /></svg>  // no theme integration
```

## 8. Typography

Theme defines all variants with the correct `clamp()` size, weight, and line-height per Foundation v1. Trust the variants. See [Typography](?path=/docs/foundation-tokens-typography--docs).

<Compare>
  <Do caption="MUI variants, default weights">
    <div style={{ color: "var(--rezics-color-text-primary)" }}>
      <div style={{ fontFamily: "var(--rezics-font-sans)", fontSize: "clamp(28px, 1.75rem + 0.8vw, 36px)", fontWeight: 600, lineHeight: 1.3 }}>
        Recent Reviews
      </div>
      <div style={{ fontFamily: "var(--rezics-font-sans)", fontSize: "clamp(14px, 0.875rem + 0.2vw, 16px)", lineHeight: 1.55, marginTop: 12 }}>
        Lorem ipsum dolor sit amet — body text rendered at base size.
      </div>
      <div style={{ fontFamily: "var(--rezics-font-sans)", fontSize: 12, color: "var(--rezics-color-text-secondary)", marginTop: 8 }}>
        3 days ago
      </div>
    </div>
  </Do>
  <Dont caption="Fixed px + heavy weight + tight leading">
    <div>
      <div style={{ fontSize: 24, fontWeight: 700, lineHeight: 1.2, color: "#1d1d1f" }}>
        Recent Reviews
      </div>
      <div style={{ fontSize: 14, lineHeight: 1.2, marginTop: 8 }}>
        Body that suffocates because line-height is below the 1.55 minimum.
      </div>
    </div>
  </Dont>
</Compare>

```tsx
// Do
<Typography variant="h2">Recent Reviews</Typography>
<Typography variant="body1">Lorem ipsum…</Typography>
<Typography variant="caption" color="text.secondary">3 days ago</Typography>

// Do — serif for the reader
<Box sx={{ fontFamily: 'var(--rezics-font-serif)', lineHeight: 1.6 }}>
  {chapterContent}
</Box>

// Don't
<h2 style={{ fontSize: 24, fontWeight: 700, lineHeight: 1.2 }}>Recent Reviews</h2>
<Typography variant="h1" fontWeight={700}>Books</Typography>  // theme default 500 is correct
```

## 9. Spacing

`theme.spacing(1)` = 8px = `space-2`. Keep multiples on the 4/8 grid; don't escape with arbitrary px.

```tsx
// Do
<Box sx={{ p: 2, gap: 4 }} />
<div className="p-2 gap-4" />

// Don't
<Box sx={{ p: '13px', gap: '22px' }} />
<div className="p-[13px] gap-[22px]" />
```

If the closest token feels wrong, propose a token addition — don't bypass.

## 10. Mode (light / dark) handling

Tokens auto-switch via `<html data-theme="dark">`. Never branch on `palette.mode` in component code.

```tsx
// Do — works in both modes, no branching
<Box sx={{ bgcolor: 'background.default', color: 'text.primary' }}>
  <Typography>Auto light/dark.</Typography>
</Box>

// Don't
const theme = useTheme();
const bg = theme.palette.mode === 'dark' ? '#1a1a18' : '#f5f4ed';
<Box sx={{ bgcolor: bg }} />
```

If a token doesn't exist for what you need, propose a token — don't branch on mode.

## 11. Mock data convention

Frontend-First development: mock the data and move forward. Annotate every placeholder with `// MOCK:` so `grep -r "// MOCK:"` finds them when the backend lands.

```ts
// Do
// MOCK: view count derived from book id hash
function mockViewCount(id: string | number): number {
  return (hashCode(String(id)) % 5000) + 10;
}

// MOCK: deterministic placeholder reviews until /api/reviews is implemented
const mockReviews: Review[] = [/* … */];

// Don't — silent placeholder, impossible to find later
const reviews: Review[] = [{ id: 1, title: 'Great book', body: '…' }];
```

## 12. Admin vs App density

Admin is operations and management — dense tables, terse copy. The app side is browsing and reading — generous rhythm.

<Compare>

```tsx
// Admin — dense (space-3 / space-4)
<TableRow sx={{ height: 40 }}>
  <TableCell sx={{ py: 1.5, px: 2 }}>{user.name}</TableCell>
  <TableCell sx={{ py: 1.5, px: 2 }}>{user.email}</TableCell>
</TableRow>

// App — generous (space-8)
<Stack spacing={4} sx={{ py: 8 }}>
  <BookSection />
  <ReviewSection />
  <ShelfSection />
</Stack>
```

Admin ≠ App. Don't replicate app-side layouts in admin; the audiences and tasks differ.

## Core purpose

A collection expresses why a person or community puts Units together: a read-later list, favourites, a themed reading list, a watch list, or long-running curation. Its name, description, order, and publication context form its own content identity.

This product was formerly called a bookshelf. It is now consistently called a collection; “bookshelf” is reserved for a possible future visual mode.

## What is available now

1. Create collections with a name, summary, visibility, and multilingual presentation.
1. Add Units of different kinds and manage members and order.
1. Preserve stable nodes and published revisions with collection structure.
1. Present collection content and owner context on a public detail page.
1. Publish a collection to a Realm for discovery in community feeds and curation surfaces.
1. Let other products refer to the same set by collection ID.

## Value for web novels

Readers can create to-read, ongoing, completed, or themed lists; Realms can curate cross-language, cross-platform recommendations. Members point to work identities, so a list remains correct when a source URL or translated title changes.

## In development

Nested views could place reviews below their corresponding work Units; bookshelf views could provide the consistent browsing experience of a game-platform library; and dynamic collections could continuously derive content from search and tag conditions. These modes still need to be justified by product requirements and preference settings, and not all are implemented.

A cross-platform collection must not create only a URL entry. The ideal flow resolves the work for a URL, retains source evidence, and inherits the tags and metadata the community has already established.

## Relationships and boundaries

A collection is not a series, tag result, or file folder. A series expresses formal work relationships, tags provide classification vocabulary, and a collection preserves its creator's organizing intention and order.

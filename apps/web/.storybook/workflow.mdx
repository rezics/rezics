# REZICS component workflow

Use these stories to inspect real shared controls and Web components with the
application's theme and typed translations. The toolbar selects the interface
language, fixture content language, light or dark theme, and viewport.

## Work with an agent

From the repository root:

```sh
task aspire:storybook
task aspire:describe
task apps-web:storybook:skills -- stories
task apps-web:storybook:tools -- docs list --withStoryIds true
task apps-web:storybook:tools -- stories changed
task apps-web:storybook:test
```

Read each tool's `--help` before using its arguments. Use discovered story IDs and
the actual Aspire resource port for focused tests, previews and Review. Each
resource exposes its own MCP URL; never assume another checkout's fixed port.

## Authoring

Write CSF Next stories beside feature components. Shared UI stories belong to the
UI workspace, outside its upstream SharkUI mirror. Use the owning preview factory
so providers, styles, and addon types are present in both Storybook and Vitest.

Document realistic inputs and distinct states. Use interaction tests for outcomes
such as a changed selection, toggled vote, retry callback, or restored focus.
Fixture support may be shared; production modules must never import stories or
fixture data. API-backed scenarios use MSW with explicit endpoint handlers.

## Screenshots and acceptance

The AI inspects screenshots of the new and changed states to find UI problems.
Passing tests and publishing links do not replace viewing the actual images.
Use browser capture tools on the selected previews, or the explicit
`storybook:capture` task with story file filters. Generated images remain under
`.temp/storybook/` and are never committed. Normal passing tests produce no images;
failure diagnostics remain available. There is no default pixel-baseline workflow.

The CSS check verifies that Tailwind utilities reach the browser. Component,
accessibility, and screenshot results cover the selected stories. Vinext server
behavior, full application flows, and deployment need their own acceptance.

Agentic Review groups related rendered stories for human inspection. It is an
agent-curated view of the work, not an exhaustive coverage report.

## Why

The `establish-design-system` change shipped tokens. The `deprecate-mui` change removed MUI and committed to shadcn-or-custom. Proposals 1 and 2 in this trilogy clean up the token architecture and migrate consumer code to the curated short-name API. With those landed, the design system has the *engineering* in place — but **the documentation is still partial, and several Apple/MD3 hybrid concepts (density, state-layer treatment, depth-without-shadow) exist in tokens but not in any place a designer or contributor could *find* them**.

The codebase audit makes the documentation gap concrete:

- **74 components** total exist in `@rezics/ui` — 39 shadcn primitives, 14 rezics primitives, 21 rezics composites.
- **35 components have stories** (47.3%). The story coverage breaks down: 0% of shadcn primitives, 92.9% of rezics primitives, 100% of rezics composites.
- **Foundation pages do not exist.** `design-system-storybook/spec.md` Requirement-4 calls for six MDX galleries under `Foundation/Tokens` — colors, typography, spacing, radius, elevation, motion. The storybook structure is in place; the MDX files are not.
- **Patterns pages do not exist.** `design-system-voice-patterns/spec.md` requires a Voice doc and a Patterns doc; neither has been authored as MDX.
- **Density is undocumented and uninstrumented.** The user identified density as per-component cross-cutting (compact / comfortable / spacious): tables and editors compact, hero and reading comfortable. The MD3 4dp-step density model has been adopted in proposal 1 as a system-tier token, but no implementation surface exists — components don't react to a `data-density` attribute, and there is no Storybook control to demo the three modes side by side.
- **Apple HIG and MD3 research is in hand but not synthesized.** Apple's "materials over shadows" elevation, the 4-tier label hierarchy, the spring-default motion sensibility, the 44pt touch target — all align with rezics' borderless-parchment direction. MD3's 8/12/12/16 state-layer ladder, the 16-step motion duration ladder, the surface-container ladder, the role vocabulary — engineering rigor that informs the rezics token system. The hybrid (MD3 architecture + Apple visual sensibility) is the rezics design philosophy. It needs to be documented, not just implicit.

The user's original P1 statement: "After abandoning MUI, need a fully documented REZICS Design system, with research from Apple HIG and Material Design 3, and a full Storybook in `package/ui`." This change is that documentation.

Why this matters in practice:

- **Discoverability.** A contributor (human or AI) reading the codebase today learns about tokens by reading `tokens/colors.ts`, learns about voice by hunting through `design-system-voice-patterns/spec.md` text, learns about density by stumbling onto a `data-density` attribute in one composite. There is no entry point that says "open Storybook, look here." After this change, opening `bun -F @rezics/ui storybook` lands on a Foundation page and the structure is self-evident.
- **Designer-developer interface.** When a designer wants to validate a color decision (will `surface-container-low` clear contrast in dark mode? will `primary-container` read as quieter-than-fill?), the answer today requires running the app or reading tokens.css. After this change, it's a Storybook page with live swatches + contrast badges.
- **Coverage matrix.** With 39 shadcn primitives at 0% story coverage, designers can't validate the rezics-aligned restyling of those primitives without running the app and finding a callsite. Adding stories to all 39 primitives surfaces gaps (which primitives still have MUI-era defaults vs which match the rezics aesthetic) and gives the design system a true regression net.
- **Density as a real, demonstrated feature.** Today density is a concept; after this change it's three buttons in a Storybook toolbar that flip every demoed component between compact / comfortable / spacious in real time. That changes density from "we say it works" to "we can show it works and break our own surfaces if it doesn't."

## What Changes

- **ADDED**: `design-system-density` capability — codifies the three-mode density system (compact / comfortable / spacious), the implementation surface (`data-density` attribute on a scope element, propagated via CSS `:where([data-density="…"])` selectors and corresponding component-tier tokens), the four-step MD3-inspired spacing offset (`-rezics-sys-density-step` set to `-2px`, `0px`, `+2px` for compact / comfortable / spacious respectively — half-step sizing keeps mode boundaries gentle), and the rule that density affects *only* spacing/sizing, never typography. Documents which rezics components opt into density and which always render at the comfortable default.
- **ADDED**: Foundation pages under `Foundation/Tokens` in the `@rezics/ui` Storybook — six MDX galleries already specified (colors, typography, spacing, radius, elevation, motion) plus a seventh: `Foundation/Tokens/Iconography`. Each gallery is a live token visualization (swatches, samples, side-by-side comparisons) with research-grounded notes calling out the Apple HIG / MD3 source and the rezics-specific divergence.
- **ADDED**: `Foundation/Patterns` pages — Apple-borderless / parchment voice (the rezics philosophy stated explicitly with do-and-don't pairs), Density triad (live mode-switcher demo with a small set of representative composites), State-layer treatment (hover/focus/pressed/dragged demos showing the 8/12/12/16 ladder applied as quiet rectangular tints, contrasted against MD3's full-bleed ripple as a "we don't do this" example), Depth without shadow (live demo of the surface-container-low / -container / -high ladder as the rezics depth mechanism, with shadow as an explicit fallback for modals only), Abstraction vs split (already specified in `design-system-storybook` spec — moving from spec to MDX), Inverse-surface emphasis (when to use `inverse-surface` and when not), Layout & breakpoints (single page covering the rezics breakpoints, container widths, the `xsm:450px` and `8xl:1440px` rezics-specific additions).
- **ADDED**: Stories for all 39 shadcn primitives in `@rezics/ui` — one CSF file per primitive, each covering at minimum: the default rendering, every named variant, disabled state, loading state (where applicable), and an "Inside a card / Inside a dialog / Inside a sidebar" embedded scenarios for primitives where the surrounding surface affects the read. The story files are co-located in `package/ui/src/shadcn/<primitive>/<Primitive>.stories.tsx`.
- **CHANGED**: `design-system-storybook` capability — adds Requirements covering the seven Foundation pages (with the iconography seventh gallery added), the new Patterns pages (parchment voice, density, state-layer treatment, depth without shadow, inverse-surface, layout & breakpoints), the global Density toolbar (toolbar entry alongside the existing Light/Dark toggle), and the shadcn-primitive 100% coverage requirement.
- **CHANGED**: Each rezics composite story file (`package/ui/src/composite/<…>.stories.tsx`) gains a Density-axis story showing the same composite at compact / comfortable / spacious side-by-side, where the composite is a density opt-in component.
- **CHANGED**: `package/storybook-config/src/preview.tsx` — adds the global density toolbar (Compact / Comfortable / Spacious) using Storybook's globalTypes, alongside the existing theme toggle. The toolbar updates `[data-density]` on the preview's wrapper element. Theme and density are independent axes; switching one does not reset the other.
- **CHANGED**: `package/ui/src/composite/` files that opt into density (Table, ListItem, Toolbar, FormControl, Sidebar item, Editor toolbar, etc. — full list defined in `design-system-density/spec.md`) consume `--rezics-sys-density-step` via the corresponding component-tier `--rezics-comp-<component>-padding-y`/`-x` tokens. Components that do *not* opt in (hero sections, reading view, cards displaying book covers) reference fixed spacing tokens, not density-relative ones.
- **ADDED**: Storybook a11y panel SHALL surface the contrast invariant (proposal 1's contrast script) inline in the Foundation/Tokens/Colors page — each swatch SHALL display its computed contrast against the current foreground role and a pass/fail badge.
- **ADDED**: Storybook MDX docs source the live token values via the existing `_gallery.tsx` helper (already specified in `design-system-storybook` spec). The helper gains exports for the new Patterns demos: `<DensityDemo>`, `<StateLayerDemo>`, `<DepthDemo>`, `<InverseSurfaceDemo>`. The helper's structure is unchanged; the surface area grows.
- **ADDED**: The `design-system-foundation` and `design-system-voice-patterns` capability deltas authored in proposal 1 / proposal 2 are *referenced* by Storybook MDX, so the spec text and the Storybook docs cannot drift. Storybook MDX uses MDX-imports from the spec source where that's clean; otherwise inlines short summaries with a link.
- **NOT IN SCOPE**: Component visual restyling. Stories document the existing visual state of every primitive; if a primitive looks wrong (e.g. a shadcn primitive still has MUI-era defaults bleeding through), it is captured in a follow-up issue, not fixed in this change.
- **NOT IN SCOPE**: Multi-package Storybook composition changes. The host + 5-package topology specified in `design-system-storybook` Requirement-2 is preserved as-is.
- **NOT IN SCOPE**: Adding new component primitives. The "custom primitives are added on demand" rule still applies.
- **NOT IN SCOPE**: Migrating sample data shown in stories away from `// MOCK:`-comment fixtures. Story fixtures are defined in `*.fixture.ts` files per the existing `MOCK convention` user feedback memory.
- **NOT IN SCOPE**: Storybook composition into a public-facing documentation site. The Storybook builds remain workspace-internal; deploy decisions are out of scope.
- **NOT IN SCOPE**: Server, contract, backend, or routing changes. Frontend documentation and density implementation only.

## Capabilities

### New Capabilities

- `design-system-density`: The per-component three-mode density system. Codifies the implementation surface (`data-density` attribute scope, component-tier tokens, the `:where()` selector pattern), the spacing-only constraint (typography never changes), the opt-in component list, and the Storybook global toolbar that demos the three modes.

### Modified Capabilities

- `design-system-storybook`: Adds Requirements covering the seven Foundation pages (Colors / Typography / Spacing / Radius / Elevation / Motion / Iconography), the six Patterns pages (Parchment Voice / Density / State Layer / Depth Without Shadow / Inverse Surface / Layout & Breakpoints), the shadcn-primitive 100% story coverage requirement (39 primitives), and the global Density toolbar wired alongside the Light/Dark theme toggle.
- `design-system-voice-patterns`: References to Storybook patterns pages added; the spec text retains its authority but each pattern gains a "demo: see Foundation/Patterns/<Page>" link.

## Impact

- **Affected packages**:
  - `@rezics/ui` (`package/ui`) — most impact. All 39 shadcn primitives gain stories. Foundation MDX pages added under `package/ui/src/docs/tokens/`. Patterns MDX pages added under `package/ui/src/docs/patterns/`. Composite story files gain Density-axis variants for opt-in components. Component-tier tokens for density-aware components added under `package/ui/src/config/tokens.css` (extending proposal 1's ~10-token component tier with another ~20 entries for density-aware spacing).
  - `@rezics/storybook-config` (`package/storybook-config`) — `src/preview.tsx` adds the density global toolbar entry. `_gallery.tsx` helper gains the Patterns-demo exports. No shape change to the package's exports.
  - `@rezics/admin`, `@rezics/app`, `@rezics/folio` — minor: their composites that opt into density (admin tables, app sidebar items, etc.) update className strings to consume the new `--rezics-comp-*-padding-*` tokens. ~10 files per package estimated.
- **Files added (estimate)**: 39 shadcn-primitive `*.stories.tsx` files; 7 Foundation MDX files; 6 Patterns MDX files; ~5 new helper exports inside `_gallery.tsx`; new `design-system-density/spec.md` spec file. Total ~57 new files.
- **Files changed**: ~30. Storybook preview, composite story files (~21 files for Density-axis stories), composite source files (~30 across the three apps for density-tokens consumption).
- **Imports changed**: A few new MDX-from-spec imports inside Foundation pages (small surface). No breaking changes.
- **Dependencies**: No runtime dep changes. May add a tiny dev dep if a Storybook-controls helper is needed for the density toolbar — verify; the existing globalTypes mechanism likely covers it without new deps.
- **Backward compatibility**: Internal-only refactor. No external consumers. Components that opt out of density (the majority) are unchanged. Components that opt in flip from fixed-spacing to density-aware-spacing — the default ("comfortable") matches the previous fixed value, so visual outcome at the default density is identical.
- **Verification**:
  - `bun -F @rezics/ui run build-storybook` succeeds and emits an `index.json` listing every Foundation page, every Patterns page, every shadcn-primitive story file, and every Density-axis composite story.
  - All 6 Storybook builds (`@rezics/ui`, `@rezics/admin`, `@rezics/app`, `@rezics/folio`, `@rezics/editor`, root host) succeed.
  - The global Density toolbar visibly switches the demo composite between compact / comfortable / spacious without remount.
  - The global Density toolbar is independent of the Light/Dark toggle; both can be active in any combination.
  - `bun run check:tokens` (proposal 1's contrast script) passes — including for the new component-tier density tokens, which inherit from system-tier surface roles unchanged.
  - `bun run check:convention` passes (no R9 violations introduced).
  - Manual visual sweep: open every Foundation page (7), every Patterns page (6), and 5 representative shadcn-primitive stories. Confirm tokens render, density toggle works, contrast badges read correctly.
  - `rg "data-density" package/` returns matches in: the storybook preview wrapper, the density-aware composite source files (~30), the spec file, and nowhere else.
- **Risk**: Low. The change is mostly additive (new MDX files, new story files, new component-tier tokens). The medium-risk surface is the density-aware composite migration (~30 files across packages) — pixel parity at "comfortable" density should be guaranteed by construction (the comfortable token equals the previous fixed value), but a careful visual sweep at "compact" and "spacious" is needed. Mitigation: each density-aware composite gets a Density-axis story that visually compares all three modes side-by-side, surfacing layout breakage immediately.

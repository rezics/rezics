## Why

The `establish-design-system` change shipped tokens. The `deprecate-mui` change removed MUI and committed to shadcn-or-custom. The `unify-tokens-single-source` change retired the legacy `--rezics-*` namespace and landed the modern token architecture: `tokens/colors.ts` (single source of truth) emits flat `--colors-*` via UnoCSS preset-wind4, and `uno-config.ts`'s preflight emits the auxiliary tokens (`--font-*`, `--radius-*`, `--shadow-*`, `--duration-*`, `--easing-*`, `--state-*-opacity`). With that landed, the design system has the *engineering* in place — but **the documentation is partial, and several Apple/MD3 hybrid concepts (density, state-layer treatment, depth-without-shadow) exist in tokens but not in any place a designer or contributor could *find* them**.

The codebase audit (re-run on 2026-05-04 against the post-`unify-tokens-single-source` tree) makes the documentation gap concrete:

- **65 components** total exist in `@rezics/ui` — 30 shadcn primitives, 14 rezics primitives, 21 rezics composites. (The shadcn fork is smaller than the canonical registry; primitives such as Accordion, AlertDialog, Form, HoverCard, InputOTP, Pagination, Progress, RadioGroup, Slider, Switch, Textarea are not present.)
- **35 components have stories** (53.8%). Coverage by tier: 0% of shadcn primitives, 13/14 = 92.9% of rezics primitives (the missing one is `TextButton`), 100% of rezics composites.
- **Foundation pages: 6 of 7 exist.** `package/ui/src/docs/tokens/` already ships colors / typography / spacing / radius / elevation / motion MDX galleries authored against the modern `--colors-*` / `--font-*` / `--radius-*` namespace. **Iconography is the remaining seventh page.**
- **Patterns: 2 of 7 exist.** `package/ui/src/docs/voice.mdx` (Foundation/Voice — the parchment philosophy) and `package/ui/src/docs/patterns.mdx` (Foundation/Patterns — abstraction-vs-split + do/don't pairs) ship today. The five new pages this change adds are Density / State Layer / Depth Without Shadow / Inverse Surface / Layout & Breakpoints — they live under a new `package/ui/src/docs/patterns/` directory.
- **Density is undocumented and uninstrumented.** The user clarified that density is **per-component-type intrinsic** — `Table` row is naturally dense, hero is naturally spacious, `MenuItem` sits in between. Density is a design-time decision baked into each component type's vocabulary, not a user-facing toggle that retrofits existing components into compact/comfortable/spacious modes. There is no implementation surface today — no component-tier `--padding-*` vocabulary exists, and there is no Storybook page that visualizes how the rezics density tiers relate.
- **Apple HIG and MD3 research is in hand but not synthesized.** Apple's "materials over shadows" elevation, the 4-tier label hierarchy, the spring-default motion sensibility, the 44pt touch target — all align with rezics' borderless-parchment direction. MD3's 8/12/12/16 state-layer ladder, the 16-step motion duration ladder, the surface-container ladder, the role vocabulary — engineering rigor that informs the rezics token system. The hybrid (MD3 architecture + Apple visual sensibility) is the rezics design philosophy. It needs to be documented, not just implicit.

The user's original P1 statement: "After abandoning MUI, need a fully documented REZICS Design system, with research from Apple HIG and Material Design 3, and a full Storybook in `package/ui`." This change is that documentation.

Why this matters in practice:

- **Discoverability.** A contributor (human or AI) reading the codebase today learns about tokens by reading `tokens/colors.ts`, learns about voice by hunting through `design-system-voice-patterns/spec.md` text, and has no way at all to learn about density (it is undocumented and uninstrumented). There is no entry point that says "open Storybook, look here." After this change, opening `bun -F @rezics/ui storybook` lands on a Foundation page and the structure is self-evident.
- **Designer-developer interface.** When a designer wants to validate a color decision (will `surface-elevated` clear contrast in dark mode? will `text-secondary` read as quieter-than-primary?), the answer today requires running the app or reading `tokens/colors.ts`. After this change, it's a Storybook page with live swatches + contrast badges.
- **Coverage matrix.** With 39 shadcn primitives at 0% story coverage, designers can't validate the rezics-aligned restyling of those primitives without running the app and finding a callsite. Adding stories to all 39 primitives surfaces gaps (which primitives still have MUI-era defaults vs which match the rezics aesthetic) and gives the design system a true regression net.
- **Density as a documented vocabulary.** Today density is a concept; after this change it's a Foundation/Patterns page rendering each density-bearing component at its intrinsic spacing tier, with the closed nine-token `--padding-*` vocabulary visualized as a ladder (breadcrumb tightest → list-item loosest). Designers and contributors see the intended rhythm without having to read source.

## What Changes

- **ADDED**: `design-system-density` capability — codifies density as **per-component-type intrinsic**, not a user-facing toggle. Defines the closed nine-token `--padding-*` vocabulary (`table-row-y` / `list-item-y` / `toolbar-y` / `formfield-y` / `sidebar-item-y` / `tab-item-y` / `menu-item-y` / `breadcrumb-y` / `command-item-y`), each emitted by the `uno-config.ts` preflight at a fixed value (no `calc()`, no `--density-step`). Pins the typography-invariance rule and the opt-in/opt-out component lists. Same-component runtime density variants are explicitly out of scope (deferred to a future OpenSpec change if the need arises).
- **ADDED**: `Foundation/Tokens/Iconography` — the seventh Foundation gallery. (The other six — colors, typography, spacing, radius, elevation, motion — already ship; this proposal does not regress them.) Live samples at the rezics standard sizes (16 / 20 / 24 px), the canonical mapping table from former MUI icons to lucide names for the icons currently used in the codebase, the named-fallback rule (when lucide lacks a glyph, use `@tabler/icons-react`), and a "Reference" callout naming Apple SF Symbols as the deeper reference and lucide-react as the rezics adoption.
- **ADDED**: Five new `Foundation/Patterns/*` pages under `package/ui/src/docs/patterns/`:
  - `density.mdx` — visualizes the nine-token `--padding-*` vocabulary as a ladder (breadcrumb tightest → list-item loosest), shows each density-bearing component rendered at its intrinsic tier, lists the opt-in/opt-out classification, and documents the "density never affects type" rule. **No user-facing mode switcher** — this page is a vocabulary reference, not a configuration UI.
  - `state-layer.mdx` — hover/focus/pressed/dragged demos showing the 8/12/12/16 ladder applied as quiet rectangular tints, contrasted against MD3's full-bleed ripple as a "we don't do this" example.
  - `depth-without-shadow.mdx` — live demo of the surface canvas/base/elevated/subtle/sunken ladder as the rezics depth mechanism, with `shadow-modal` as the explicit fallback reserved for modals only.
  - `inverse-surface.mdx` — snackbars, dark-on-light pull-quotes, "switch to dark mode" preview button. When and when not.
  - `layout-and-breakpoints.mdx` — visual ruler of the rezics breakpoints (`xsm:450px`, `sm:640`, `md:768`, `lg:1024`, `xl:1280`, `2xl:1536`, `8xl:1440`), container widths, the rationale for `xsm` and `8xl` as rezics-specific additions.
  - The existing `voice.mdx` (Foundation/Voice) already covers the parchment-voice philosophy and is *not* replaced or duplicated; the new pages cross-link to it.
  - The existing `patterns.mdx` (Foundation/Patterns) already covers abstraction-vs-split + do/don't pairs and stays at the docs root as the index page; the new pattern detail pages live under `Foundation/Patterns/<Page>` titles.
- **ADDED**: Stories for all 30 shadcn primitives in `@rezics/ui` — one CSF file per primitive co-located at `package/ui/src/shadcn/<primitive>.stories.tsx`. Each story file covers at minimum: the default rendering, every named variant, disabled state, loading state (where applicable), and "Inside a card / Inside a dialog / Inside a sidebar" embedded scenarios for primitives where the surrounding surface affects the read. **No `WithDensity` stories** — density is per-component-type intrinsic, not a runtime toggle (see `design-system-density/spec.md`).
- **ADDED**: Story for the missing rezics primitive `TextButton` (`package/ui/src/primitive/button/TextButton.stories.tsx`).
- **CHANGED**: `design-system-storybook` capability — adds Requirements covering the seventh Iconography Foundation page, the five new Patterns detail pages (Density / State Layer / Depth Without Shadow / Inverse Surface / Layout & Breakpoints), and the shadcn-primitive 100% coverage requirement (30 primitives). The existing Light/Dark toolbar entry is preserved; **no density toolbar is added**.
- **CHANGED**: `package/ui/src/config/uno-config.ts` — the existing preflight extends to emit the nine component-tier `--padding-*` tokens (`table-row-y` / `list-item-y` / `toolbar-y` / `formfield-y` / `sidebar-item-y` / `tab-item-y` / `menu-item-y` / `breadcrumb-y` / `command-item-y`) at fixed values. **No `--density-step` system token, no `calc()` expressions, no class-based density overrides.** No new files are added to `package/ui/src/config/`; the preflight pattern already established by `unify-tokens-single-source` is the single emission surface.
- **CHANGED**: rezics-authored components (in `package/ui/src/primitive/` and `package/ui/src/composite/`) that fall in the opt-in list (Toolbar, FormField wrapper, List item composite, etc. — final list pinned in `design-system-density/spec.md`) consume the corresponding `--padding-*` token. Components that do *not* opt in (hero sections, reading view, book-cover frames, dialog content) reference the existing fixed spacing utilities, unchanged. **Vendored shadcn primitives in `package/ui/src/shadcn/` are not patched** — they consume the spacing values shadcn ships with (the rezics density vocabulary applies to rezics-authored code only; see `migrate-shadcn-to-base-ui-luma`).
- **ADDED**: Storybook a11y panel SHALL surface the contrast invariant inline in the Foundation/Tokens/Colors page — each swatch SHALL display its computed contrast against the current foreground role and a pass/fail badge. (The Colors page already ships swatches; this change adds the badges.)
- **ADDED**: `_gallery.tsx` gains exports for the new Patterns demos: `<DensityDemo>`, `<StateLayerDemo>`, `<DepthDemo>`, `<InverseSurfaceDemo>`. The 11 existing exports (`Grid`, `Swatch`, `Row`, `SpacingRuler`, `RadiusSample`, `ElevationSample`, `TypeSample`, `MotionSample`, `Do`, `Dont`, `Compare`) are unchanged.
- **NOT IN SCOPE**: Component visual restyling. Stories document the existing visual state of every primitive; if a primitive looks wrong (e.g. a shadcn primitive still has MUI-era defaults bleeding through), it is captured in a follow-up issue, not fixed in this change.
- **NOT IN SCOPE**: Multi-package Storybook composition changes. The host + 5-package topology specified in `design-system-storybook` Requirement-2 is preserved as-is.
- **NOT IN SCOPE**: Adding new component primitives. The "custom primitives are added on demand" rule still applies.
- **NOT IN SCOPE**: Migrating sample data shown in stories away from `// MOCK:`-comment fixtures. Story fixtures are defined in `*.fixture.ts` files per the existing `MOCK convention` user feedback memory.
- **NOT IN SCOPE**: Storybook composition into a public-facing documentation site. The Storybook builds remain workspace-internal; deploy decisions are out of scope.
- **NOT IN SCOPE**: Server, contract, backend, or routing changes. Frontend documentation and density implementation only.

## Capabilities

### New Capabilities

- `design-system-density`: Per-component-type intrinsic density vocabulary. Codifies the closed nine-token `--padding-*` set emitted as fixed values by the existing `uno-config.ts` preflight, the spacing-only constraint (typography never changes), and the opt-in / opt-out component classification. Same-component runtime density variants are explicitly out of scope.

### Modified Capabilities

- `design-system-storybook`: Adds Requirements covering the seven Foundation pages (Colors / Typography / Spacing / Radius / Elevation / Motion / Iconography), the seven Patterns pages (Voice / Patterns / Density / State Layer / Depth Without Shadow / Inverse Surface / Layout & Breakpoints), and the shadcn-primitive 100% story coverage requirement (30 primitives). The existing Light/Dark toolbar entry is preserved; no density toolbar is added.
- `design-system-voice-patterns`: References to Storybook patterns pages added; the spec text retains its authority but each pattern gains a "demo: see Foundation/Patterns/<Page>" link.

## Impact

- **Affected packages**:
  - `@rezics/ui` (`package/ui`) — most impact. All 30 shadcn primitives gain stories. The seventh Iconography Foundation MDX page added under `package/ui/src/docs/tokens/`. Five Patterns MDX pages added under a new `package/ui/src/docs/patterns/` directory. The nine component-tier `--padding-*` tokens emitted at fixed values by extending the existing preflight in `package/ui/src/config/uno-config.ts` — no new file in `config/`, no resurrection of `tokens.css` (R9 forbids it). No `--density-step` introduced.
  - `@rezics/storybook-config` (`package/storybook-config`) — `_gallery.tsx` helper gains four Patterns-demo exports. **`src/preview.tsx` is unchanged** (no density toolbar). No shape change to the package's exports.
  - `@rezics/admin`, `@rezics/app`, `@rezics/folio` — minor: rezics-authored composites in the opt-in list (custom List items, FormField wrappers, etc. — *not* the vendored shadcn primitives) update className strings to consume the new `--padding-*` tokens. **No `<html class="density-*">` writes on app mount** — density is intrinsic to the component, not a per-app preference. ~5 files per consumer package estimated.
- **Files added (estimate)**: 30 shadcn-primitive `*.stories.tsx` files; 1 Foundation MDX file (Iconography); 5 Patterns MDX files; 1 rezics-primitive story (`TextButton.stories.tsx`); 4 new helper exports inside `_gallery.tsx`; new `design-system-density/spec.md` spec file. Total ~38 new files.
- **Files changed**: ~20. `uno-config.ts` (preflight extension for the nine `--padding-*` tokens), `_gallery.tsx` (helper exports), rezics-authored composite source files (~10 across the three apps for density-token consumption). `preview.tsx` is **not** modified.
- **Imports changed**: No breaking changes. New MDX pages import from `_gallery.tsx`.
- **Dependencies**: No runtime dep changes. No new dev deps.
- **Backward compatibility**: Internal-only refactor. No external consumers. Components that opt out of density (the majority) are unchanged. Components that opt in flip from inline fixed-spacing utilities to a CSS-variable reference resolving to the same fixed value — visual outcome is identical by construction.
- **Verification**:
  - `bun -F @rezics/ui run build-storybook` succeeds and emits an `index.json` listing all 7 Foundation pages, 7 Patterns pages (2 existing + 5 new), and all 30 shadcn-primitive stories.
  - All 5 Storybook builds (`@rezics/ui`, `@rezics/admin`, `@rezics/app`, `@rezics/folio`, `@rezics/editor`) plus the root host succeed.
  - `rg "--density-step|density-compact|density-spacious" package/` returns **zero matches** in source (only acceptable matches: this proposal's `proposal.md`/`design.md` describing what was *not* introduced, and the spec file forbidding them).
  - `bun run check:tokens` passes (proposal 1's contrast script — should be unaffected; verify).
  - `bun run check:convention` passes — R9 must not regress (no `--rezics-*` references introduced; `tokens.css` does not appear).
  - Manual visual sweep: open every Foundation page (7), every Patterns page (7), and 5 representative shadcn-primitive stories. Confirm tokens render and contrast badges read correctly.
  - `rg "var\(--padding-" package/` returns matches in: the preflight emitter (`uno-config.ts`), rezics-authored composite source files (~10), the spec file, and nowhere else (specifically, no matches inside `package/ui/src/shadcn/`).
- **Risk**: Low. The change is mostly additive (new MDX, new story files, new tokens emitted by preflight extension). The medium-risk surface is the rezics-authored composite token migration (~10 files across packages) — pixel parity is guaranteed by construction (each `--padding-*` resolves to the same fixed value the component used inline before).

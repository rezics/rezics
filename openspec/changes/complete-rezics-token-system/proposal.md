## Why

The `deprecate-mui` change established `--rezics-*` as the project's token namespace and aligned shadcn primitives to those tokens. With MUI gone, the token system's seams are visible — and four of them are load-bearing for everything that comes next:

1. **Two generations of color names co-exist.** `rezics-color-fg` / `rezics-color-fg-muted` (260 references) overlaps `rezics-color-text-primary` / `rezics-color-text-secondary` (newer ladder). `rezics-color-bg` / `rezics-color-bg-muted` (47 references) overlaps `rezics-color-surface-canvas` / `rezics-color-surface-subtle`. `rezics-color-primary` / `rezics-color-secondary` / `rezics-color-accent` (57 references) overlap `rezics-color-brand-fill` and the newer surface ladder. Each generation works individually; the overlap means a contributor reading the codebase has no way to tell which name is "correct" without external context. Total dual-generation consumption: 364+ references across 60+ files.

2. **shadcn slots are partially absorbed and partially aliased to the wrong rezics name.** The `.theme-rezics` block in `package/ui/src/shared/styles/layers.css` covers all 22 standard shadcn slots, but several alias to a rezics name that is *itself* legacy (e.g. `--secondary` → `rezics-color-surface-subtle`, which conflates "secondary container" with "muted surface"). Crucially, the shadcn vocabulary lacks `primary-container` / `error-container` / the `surface-container-{low,default,high,highest}` ladder / `inverse-surface` / `inverse-primary` — the exact roles a parchment-and-borderless aesthetic needs to express depth and emphasis without shadows. `--radius` holds a literal `0.5rem` instead of aliasing `--rezics-radius-md`. The shadcn surface is *consumed* but is not yet a *superset* of MD3's role vocabulary, which is what the rezics aesthetic actually needs.

3. **`layers.css` conflates four concerns.** Today it owns: (a) the rezics token table at `:root`, (b) the dark-mode override block, (c) the `.theme-rezics` shadcn binding block, (d) global resets (`:lang()` font routing, `prefers-reduced-motion`). Splitting tokens from baseline is the precondition for adding a state-layer system, motion/easing tokens at the system tier, and the density attribute scope — none of which can land cleanly while baseline and tokens cohabit one file.

4. **The CSS variable strategy is implicit.** The current namespace works (`--rezics-color-text-primary` at `:root`, overridden under `[data-theme="dark"]`), but the choice between *prefix-on-each-var* and *wrapped-unprefixed-under-selector* was never explicit. As we add token tiers (reference / system / component) and the chart palette / sidebar chrome / state-layer opacities, that implicit choice starts costing: every new namespace has to invent its own naming and switching mechanism.

The MD3 architecture (3-tier ref/sys/comp tokens, role vocabulary including `primary-container` / `error-container` / `surface-container-*` ladder / `inverse-surface`, 8/12/12/16 state-layer opacities, motion duration + easing scales, density-as-spacing-step) is the strongest off-the-shelf engineering for this. Apple HIG's `materials-over-shadows` philosophy and 4-tier label hierarchy align with the existing rezics borderless-parchment aesthetic. Neither maps to rezics 1:1 — but the hybrid (MD3 architecture + Apple visual sensibility) is what the design system has informally been doing since `establish-design-system`. This change makes it explicit.

## What Changes

- **CHANGED**: Token vocabulary architecture moves from a flat single-tier (`--rezics-color-*` at `:root`) to a three-tier model:
  1. **Reference tier** (`--rezics-ref-*`) — raw palette, type ramp, spacing scale, radius scale. Mode-invariant. Hand-curated, not algorithmic.
  2. **System tier** (`--rezics-sys-*`) — semantic roles. Light/dark resolved here by remapping system tokens to different reference values. This tier owns the role vocabulary (text-primary / surface-canvas / brand-fill / state-hover-opacity / motion-duration-base / etc.).
  3. **Component tier** (`--rezics-comp-*`) — only authored where a component's mapping is non-obvious. Most components reference system tokens directly via UnoCSS theme classes; the component tier is reserved for cases like "the quiet button uses primary-container, not primary" where the binding deserves a name.
- **CHANGED**: rezics absorbs shadcn's 22-slot vocabulary as a *strict superset*. The shadcn slots remain authored as flat unprefixed vars (`--card`, `--primary`, `--background`, …) and resolve to the same rezics system tokens that UnoCSS theme classes resolve to. There is one source of truth per role, exposed under two names — the rezics name (used by application code via UnoCSS short classes) and the shadcn name (used by shadcn primitive internals). New superset additions: `primary-container` / `on-primary-container`, `error-container` / `on-error-container`, `surface-container-{low,default,high,highest}` ladder, `outline-variant` (separate from `outline`), `inverse-surface` / `inverse-primary` / `inverse-on-surface`, `surface-tint`. Each resolves to a rezics-curated value, not an MD3 algorithmic tone.
- **CHANGED**: Theme-scoping strategy is **Strategy B (wrapped-unprefixed-under-selector)**. The full token table — reference, system, component, *and* shadcn-superset slots — is authored once under `.theme-rezics { … }` rather than at `:root` with a `--rezics-` prefix on each variable. Dark mode is a sibling block: `.theme-rezics[data-theme="dark"] { … }` overrides the system tier. The `.theme-rezics` selector SHALL be applied to `<html>` (not a subtree), so portal-rendered components — modals, tooltips, dropdowns rendered into `document.body` — inherit the same cascade as the in-tree app. The `--rezics-*` prefix is retained for the system-tier vars that are also exposed to UnoCSS theme classes (so `--rezics-color-text-primary` survives), but the new ref/comp tiers and the shadcn-superset slots SHALL NOT carry the prefix when their consumer is internal.
- **CHANGED**: File split. `package/ui/src/shared/styles/layers.css` is replaced by:
  - `package/ui/src/config/tokens.css` — the entire `.theme-rezics` token table (ref, sys, comp, shadcn-superset slots) and the `[data-theme="dark"]` override block. Authored alongside `uno-config.ts` so theme changes touch one folder.
  - `package/ui/src/config/base.css` — `:lang()` font routing, `prefers-reduced-motion` global, the small set of legacy resets that previously cohabited `layers.css`. Imported once at the app entry, not by Storybook (Storybook gets baseline from its own preview).
  - The eight files currently importing `layers.css` (3 storybook previews, 2 storybook configs, 2 app shells, 1 uno-config) are repointed to import `tokens.css` and (where applicable) `base.css` directly.
- **CHANGED**: `package/ui/components.json` `tailwind.css` path moves from `src/shared/styles/layers.css` to `src/config/tokens.css`. Future shadcn CLI runs read tokens from the canonical location.
- **CHANGED**: `package/ui/src/config/uno-config.ts` is reviewed against the codebase audit. Every override is *kept* — the audit confirms 99% are brand-specific (Foundation v1 colors) or architectural (minimal shadow palette, semantic motion names, brand fonts with CJK routing) and 0% are redundant restatements of Tailwind v4 defaults. The one cosmetic change: `borderRadius` and `boxShadow` mappings are reviewed once to confirm every key is either a value Tailwind v4 lacks (`pill`, `full`, `modal`) or differs from the v4 default (every rezics radius does). No keys are removed.
- **CHANGED**: Dual-generation token names are consolidated at the *definition* site. The legacy names — `rezics-color-fg`, `rezics-color-fg-muted`, `rezics-color-bg`, `rezics-color-bg-muted`, `rezics-color-bg-canvas`, `rezics-color-bg-elevated`, `rezics-color-bg-hover`, `rezics-color-bg-selected`, `rezics-color-primary`, `rezics-color-secondary`, `rezics-color-accent` — are kept as *aliases* in `tokens.css` (each one resolves to its successor via `var()` chain) so the migration in proposal 2 (`migrate-to-theme-config-classes`) can land independently. Aliases are marked `@deprecated` in a comment block; once proposal 2 retires the last consumer, a follow-up change deletes them.
- **ADDED**: State-layer opacity tokens at the system tier — `--rezics-sys-state-hover-opacity: 0.08`, `--rezics-sys-state-focus-opacity: 0.12`, `--rezics-sys-state-pressed-opacity: 0.12`, `--rezics-sys-state-dragged-opacity: 0.16`. The MD3 8/12/12/16 ladder is adopted verbatim — these are the single best-engineered numbers in MD3, contrast-tested across thousands of role pairs, and they map cleanly onto a rezics quiet-rectangular-tint visual treatment (no ripple, no full-bleed). UnoCSS theme exposure: `bg-state-hover` / `bg-state-focus` / `bg-state-pressed` shortcuts that emit a translucent overlay using the closest `on-*` role.
- **ADDED**: Motion system tokens at the system tier — `--rezics-sys-motion-duration-{short1,short2,short3,short4,medium1,medium2,medium3,medium4,long1,long2,long3,long4,extra-long1,extra-long2,extra-long3,extra-long4}` (the 16-step MD3 ladder, 50ms–1000ms) and `--rezics-sys-motion-easing-{standard,emphasized,emphasized-decelerate,emphasized-accelerate,linear}` (cubic-bezier curves verbatim from MD3). The current rezics motion vars (`fast/base/slow/page` + `out/in-out/spring`) are kept as *named aliases* mapping into the new ladder — `fast` → `short3` (150ms), `base` → `medium1` (250ms), `slow` → `medium4` (400ms), `page` → `long2` (500ms), `spring` retains its custom cubic-bezier as a non-MD3 rezics-specific easing.
- **ADDED**: Surface-container ladder at the system tier — `--rezics-sys-color-surface-container-lowest`, `-low`, `-container`, `-high`, `-highest`. Realized as a five-step parchment tint (each step is a small lightness shift, not a shadow). Replaces the implicit "depth = box-shadow" pattern with a tonal model that fits the borderless aesthetic. UnoCSS exposure: `bg-surface-container-low` / `bg-surface-container-high` / etc.
- **ADDED**: Container color variants at the system tier — `primary-container` / `on-primary-container`, `error-container` / `on-error-container`. These are the quieter, container-shaped variants used by chips, badges, quiet-buttons, and tonal banners. The brand role family expands from `brand-fill` / `text-on-brand` (single tier) to `brand-fill` / `text-on-brand` / `brand-container` / `text-on-brand-container` (two tiers). `error-fill` / `error-container` likewise.
- **ADDED**: Inverse roles at the system tier — `inverse-surface`, `inverse-primary`, `inverse-on-surface`. Used by snackbars, dark-on-light pull-quotes, the "switch to dark mode" preview button, and any UI element that needs to break the prevailing surface contrast for emphasis.
- **ADDED**: Chart palette tokens at the system tier — `--rezics-sys-color-chart-{1,2,3,4,5}` resolving to a curated rezics 5-step palette (replacing the literal OKLCH values currently inlined in the `.theme-rezics` block). The shadcn `--chart-1..5` slots alias to these.
- **ADDED**: Sidebar chrome tokens at the system tier — `--rezics-sys-color-sidebar-{background,foreground,primary,primary-foreground,accent,accent-foreground,border,ring}`. Each resolves to a rezics value; the shadcn `--sidebar*` slots alias to these.
- **NOT IN SCOPE**: Migrating consumer code from long-form `text-rezics-color-*` to short-name `text-text-primary` (that is proposal 2: `migrate-to-theme-config-classes`).
- **NOT IN SCOPE**: Storybook foundation pages, MDX galleries, density model, voice/patterns docs (that is proposal 3: `complete-rezics-design-storybook`).
- **NOT IN SCOPE**: Adding new component primitives. Custom primitive policy from `ui-component-foundation/spec.md` Requirement-5 ("Custom primitives are added on demand, not preemptively") still applies.
- **NOT IN SCOPE**: HCT algorithmic palette generation. rezics keeps its hand-curated palette; the MD3 contrast invariant (50-tone delta between role and on-role) is adopted as a *test* over the curated values, not a generator.
- **NOT IN SCOPE**: Server, contract, backend, or routing changes. CSS / TS / config only.

## Capabilities

### Modified Capabilities

- `ui-component-foundation`: Adds Requirements covering the three-tier token architecture (ref / sys / comp), the shadcn-superset role vocabulary (with explicit role list), the `.theme-rezics` selector strategy and its `<html>` placement requirement, the file split (`tokens.css` + `base.css` under `config/`), and the `components.json` path requirement. Adds a Requirement that prohibits new tokens at `:root` outside `tokens.css`.
- `design-system-foundation`: Adds Requirements covering the system-tier token surface — state-layer opacities, motion duration/easing ladder, surface-container ladder, container color variants, inverse roles, chart palette, sidebar chrome. Adds a Requirement that legacy generation token names (the 11-name list) are retained as `@deprecated` aliases until proposal 2 retires their consumers.

## Impact

- **Affected packages**:
  - `@rezics/ui` (`package/ui`) — the entire token surface migrates. `src/shared/styles/layers.css` is split into `src/config/tokens.css` and `src/config/base.css`. `src/config/uno-config.ts` reviewed (no overrides removed; cosmetic comment audit only). `components.json` updated. `src/config/tokens/` TS modules audited — system-tier additions (state-layer opacities, motion ladder, surface-container ladder, container variants, inverse roles, chart, sidebar) authored as TS exports if any consumer needs them in JS, otherwise CSS-only.
  - `@rezics/storybook-config` (`package/storybook-config`) — preview rewires to import the new `tokens.css` path.
  - `@rezics/app`, `@rezics/admin`, `@rezics/folio`, `@rezics/editor` — only the entry-point CSS imports change (8 files total per audit). No business-logic edits in this proposal — those land in proposal 2.
- **Files touched (estimate)**: ~20 files. 8 entry points repointed (App.tsx files + storybook previews + uno-config). 1 file split into 2 (`layers.css` → `tokens.css` + `base.css`). 1 file deleted (`layers.css` after rewires verified). `components.json` updated. `tokens/colors.ts`, `tokens/motion.ts`, `tokens/spacing.ts`, etc. amended for new system-tier exports if any. ~6 spec deltas + 3 proposal-bundle files.
- **Imports changed**: All current `@rezics/ui/shared/styles/layers.css` imports become `@rezics/ui/config/tokens.css` (and `@rezics/ui/config/base.css` where the consumer also needs the baseline globals — currently only the two app shells, not Storybook).
- **Dependencies**: No new runtime dependencies. No removals. The `@rezics/ui` package surface gains two CSS exports (`./config/tokens.css`, `./config/base.css`) and retains `./shared/styles/layers.css` as a thin re-export shim for one phase, deleted at the end.
- **Backward compatibility**: Internal-only refactor. No external consumers. Legacy generation token names (the 11-name list) are kept as live aliases through this change so consumer migration in proposal 2 can run independently.
- **Verification**:
  - `bun -F @rezics/ui run build` SHALL succeed. Type-check SHALL pass.
  - Every Storybook (`@rezics/ui`, `@rezics/app`, `@rezics/admin`, `@rezics/folio`) SHALL render with `[data-theme="dark"]` and `[data-theme="light"]` toggles correctly switching every newly-added system-tier token (verified via the contrast-test script described in `tasks.md`).
  - A manual visual sweep of the existing pages SHALL confirm no regression — the legacy aliases are still live, so no consumer code change is needed for verification.
  - A new contract test in `tool/scripts/check-tokens.ts` SHALL assert the role / on-role contrast invariant (≥4.5:1 for text-on-surface pairs, ≥3:1 for non-text UI element pairs) across light and dark modes.
  - `rg "from .@rezics/ui/shared/styles/layers.css." package/` SHALL return zero matches at the end of the change (or only the back-compat shim itself, which is then deleted in the change's last task).
- **Risk**: Low-medium. The dominant risk is portal-rendered components losing the `.theme-rezics` cascade if `<html>` is missed (e.g. the Vite dev-server sometimes doesn't see token edits before a full reload). Mitigation: a smoke test in tasks.md that boots each app in dev, opens a modal/tooltip/dropdown, and confirms the rezics tokens resolve in the portal subtree. Secondary risk: a runtime CSS-in-JS that reads `getComputedStyle()` on `:root` for a `--rezics-*` lookup will break (no such consumer is known per `rg`, but tasks.md includes a verification grep).

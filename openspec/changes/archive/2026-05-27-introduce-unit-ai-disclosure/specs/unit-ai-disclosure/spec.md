## ADDED Requirements

### Requirement: AI disclosure mode enum definition

The system SHALL define an `AiDisclosureMode` enum with exactly five canonical
members shared by the database, contract, and frontend:

- `UNKNOWN` - provenance is unknown, unset, or not asserted.
- `NONE` - the maintainer asserts no AI involvement in the Unit's declared
  public-facing content.
- `AI_ASSISTED` - human-created content with AI assistance such as editing,
  translation, formatting, summarization, or cleanup.
- `AI_ORIGINATED` - AI generated the initial or substantial draft, followed by
  meaningful human editing or review.
- `MACHINE_GENERATED` - content primarily generated by AI with little or no
  human review.

The enum members SHALL describe AI involvement/provenance and SHALL NOT be
treated as age suitability, safety severity, quality, copyright status, or a
strictly ordered risk scale.

#### Scenario: Enum identifier is shared across layers

- **GIVEN** the Prisma enum, the Typebox contract, and frontend constants
- **WHEN** an `AiDisclosureMode` value is serialized through any layer
- **THEN** it SHALL use exactly one of the identifiers `UNKNOWN`, `NONE`, `AI_ASSISTED`, `AI_ORIGINATED`, or `MACHINE_GENERATED`

#### Scenario: Disclosure modes are not rating tiers

- **WHEN** the system evaluates a Unit with `aiDisclosureMode = MACHINE_GENERATED`
- **THEN** the system SHALL NOT infer any `ContentRating` value from the disclosure mode
- **AND** the system SHALL NOT treat `MACHINE_GENERATED` as a stricter age or safety tier than `AI_ASSISTED`

### Requirement: AI disclosure is stored at Unit level

Every Unit SHALL carry a single `aiDisclosureMode: AiDisclosureMode` value at
the Unit metadata layer. The value SHALL default to `UNKNOWN` when a Unit is
created without an explicit AI disclosure mode.

The disclosure mode SHALL be declaratively set by a maintainer or trusted
system/import process. The system SHALL NOT derive the value from automated AI
detection heuristics.

#### Scenario: Default disclosure on creation

- **WHEN** a new Unit is created without specifying `aiDisclosureMode`
- **THEN** the Unit SHALL be persisted with `aiDisclosureMode = UNKNOWN`

#### Scenario: Explicit no-AI declaration

- **GIVEN** a Unit with `aiDisclosureMode = UNKNOWN`
- **WHEN** the maintainer sets `aiDisclosureMode = NONE`
- **THEN** the Unit SHALL persist `aiDisclosureMode = NONE`
- **AND** the value SHALL represent an affirmative no-AI declaration, not a missing value

#### Scenario: Disclosure update changes only the target Unit

- **GIVEN** a Book Unit with chapter Units that carry their own disclosure modes
- **WHEN** the maintainer updates the Book Unit's `aiDisclosureMode`
- **THEN** only the Book Unit's disclosure mode SHALL be changed
- **AND** none of the chapter Units' disclosure modes SHALL be modified

### Requirement: Optional AI disclosure details

The system SHALL allow optional AI disclosure details to accompany the Unit's
coarse disclosure mode. Details MAY include model, provider, human review flag,
disclosure source, and source standard. Missing details SHALL NOT invalidate an
otherwise valid `aiDisclosureMode`.

The system SHALL validate supported detail keys and value shapes at API
boundaries where details are accepted.

#### Scenario: Store coarse mode without details

- **WHEN** a maintainer sets `aiDisclosureMode = AI_ASSISTED` without details
- **THEN** the system SHALL persist the disclosure mode
- **AND** the system SHALL NOT reject the update because model or provider details are missing

#### Scenario: Store optional details

- **WHEN** a maintainer sets `aiDisclosureMode = AI_ORIGINATED` with details including `provider = "OpenAI"` and `reviewedByHuman = true`
- **THEN** the system SHALL persist the supported detail values with the Unit
- **AND** subsequent reads SHALL return the persisted details through Unit metadata responses

### Requirement: AI disclosure appears in Unit-facing responses

Unit-facing API responses SHALL expose `aiDisclosureMode` anywhere they expose
the Unit's fixed metadata fields such as `rating`, `visibility`, or
`licenseSlug`. Responses MAY include optional AI disclosure details when those
details are available to the caller.

#### Scenario: Unit detail includes disclosure mode

- **GIVEN** a Unit with `aiDisclosureMode = AI_ASSISTED`
- **WHEN** a caller loads the Unit detail response
- **THEN** the response SHALL include `aiDisclosureMode = AI_ASSISTED`

#### Scenario: Book detail mirrors Unit disclosure mode

- **GIVEN** a Book extension whose underlying Unit has `aiDisclosureMode = AI_ORIGINATED`
- **WHEN** a caller loads the Book detail response
- **THEN** the response SHALL include `aiDisclosureMode = AI_ORIGINATED` with the Book's Unit-level metadata

### Requirement: AI disclosure may be displayed and filtered separately

User interfaces that display AI disclosure SHALL present it as provenance or AI
usage disclosure, separate from age/content rating. Search or discovery filters
that use AI disclosure SHALL use explicit AI disclosure fields and SHALL NOT
reuse `rating` filters.

#### Scenario: Public display uses disclosure copy

- **GIVEN** a public Unit with `aiDisclosureMode = MACHINE_GENERATED`
- **WHEN** the Unit is shown in a metadata panel or card that includes AI disclosure
- **THEN** the UI SHALL identify the content as AI-generated or machine-generated disclosure
- **AND** the UI SHALL NOT display it as an age rating or moderation warning

#### Scenario: Search filter is independent from rating

- **GIVEN** a search request with `aiDisclosureModes = ["AI_ASSISTED"]` and no rating filter
- **WHEN** the system evaluates matching Units
- **THEN** the system SHALL filter by `aiDisclosureMode = AI_ASSISTED`
- **AND** the system SHALL NOT change the caller's allowed `ContentRating` set
